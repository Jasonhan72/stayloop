ADDENDUM · 对《三阶段可见化与三角色流程细化方案》的增补

EliseAI 产品线拆解 → Stayloop 对照与方案增补

依据用户提供的《EliseAI 产品线功能拆解》（2026-09-23 快照：LeasingAI、ResidentAI 五模块、EliseCRM、VoiceAI、Apollo、HealthAI、服务与增值、平台与集成）逐模块对照 Stayloop 现状，并把值得采用的做法并入待决定的方案。仍是方案，不含实现。
EliseAI 规模口径：$200M ARR（2026-06）、覆盖美国 1/6 公寓、600+ 业主运营商、5M+ 单元；销售主导、无公开定价、demo-only。Stayloop 面向安省小房东 / 租客 / 持牌经纪——对照的是方法，不是规模。

0 · 这份拆解改变了什么

  • ResidentAI 不是一个泛化「租中」，而是五条明确工作流（搬入 / 维修分诊 / 技师执行 / 续约 / 欠款）。我们的「租中 · 租后」两段应按同样粒度拆成可见的子工作流，每条写清「AI 负责 / 人工负责」。
  • 每个模块都带「AI 负责 / 人工负责」交接框——这正是我们「提议而不决定」的产品语言，但我们从未在页面上这样写。建议成为 /platform 与每个工作流卡片的固定栏目。
  • EliseCRM 的核心是「一张卡聚合所有触点」（Guest Card）+「任务按主题路由」：与方案里的「对象追踪器」和「待办」一一对应，可以直接借它的信息架构。
  • Apollo（内部员工的跨平台 agent，继承权限、批量执行）是我们尚未有的一层：房东对 Logic 说「给所有 60 天内到期的租客发续约函」应该能批量生成待批卡。这是 P2 的新增项。
  • Fee Transparency / Lease Audits / Move-In 文件验证三项我们其实有对应能力（费用一览 + 规则页、取证引擎、租约条款检查），只是散落在筛查里，没有以租中工具的身份出现。
  • 不抄的部分更清楚了：VoiceAI、HealthAI、Maintenance App（技师端）、催收付款计划的资金侧、神秘顾客评分、集成矩阵（我们没有 PMS 生态）。

2 · 并入方案的增补（按期）

不改方案骨架（阶段轨 P0 → 对象追踪器 P1 → 今日视图与流程能力 P2），只做四处增补：
期增补项说明
P0阶段轨每段加「AI 负责 / 你负责」两行EliseAI 每个模块的交接框。租前：AI 找房 / 筛查 / 拟通知，你决定录取；租中：AI 建单 / 提醒 / 拟稿，你批准发送；租后：AI 算方案 / 时钟，你选 A/B。/platform 同步。
P1租中拆成可见子工作流：搬入 · 报修 · 租金 · 续约对应 ResidentAI 五模块（去掉技师端）。每条一张卡，卡上有状态 + 下一步 + 交接框。
P1报修分诊字段 + 状态通知提交时 AI 抽取类别 / 紧急度 / 入户许可 / 是否有宠物（模型抽取，确定性字段）；紧急（漏水、无暖、无电、锁）标红并提示房东电话与安省维修义务；工单状态变更推送租客。
P1续约意向回流租客在 30 天触点邮件 / 共享中心一键「续 / 不续 / 谈」；房东申请人 / 租约列表显示意向；「谈」= 把对话打包成待批卡给房东（带上下文升级）。
P1租约 vs 租金记录对账Lease Audits 的小房东版：租约月租 ≠ 记录金额、押金利息未付、到期未续签仍按旧租金——纯函数提示。
P2组合级批量提议（Apollo 的房东版）「给 60 天内到期的租客都发续约函」→ 一次生成 N 张卡；「哪套空置最久 / 本月谁没交」只读回答。权限 = 只在自己的行上。
P2还款计划（安省载体）迟付后 AI 按 LTB Payment Agreement Form 的字段拟稿，双方确认后各自去 LTB 提交；Stayloop 不收款、不催收。
P2入住清单 + 租客保险单验证Move-In 的小房东版：清单（钥匙 / 水电过户 / 交接照片 / 保险）+ 保险单 PDF 走现有取证引擎验真。
P2 可选房源专属 FAQ · 语气三档 · 费用一览 PDF · 邮件回流低成本项，按需要。

3 · 明确不做（写进方案的「不抄清单」）

  • VoiceAI / 电话坐席、外呼；HealthAI；技师 App 与调度台；群发活动；情绪分析；神秘顾客评分；智能锁自助看房；PMS 集成矩阵；催收话术与资金侧（Stayloop 不经手租金，也不做催收）。
  • 任何「筛选标准 / 转化目标」的可配置截止线（OHRC 租房政策）。
  • 百分比效果数字（EliseAI 的 −65% / +9% / 99% 都是客户案例口径，我们没有可审计对照组）。

4 · 对待决定事项的影响

原方案第 6 节的 6 个决策点不变，新增 2 个：⑦ 租中是否按「搬入 · 报修 · 租金 · 续约」四条子工作流拆开显示（P1）；⑧ 是否做房东组合级批量提议（P2，Apollo 的房东版）。建议：⑦ 做，⑧ 等 P0/P1 上线后看房东是否有多套房源再做。
