# Stayloop 全站测试规范（v1 · 2026-09-22）

适用范围：www.stayloop.ai（Next.js 15 App Router · Cloudflare Pages · Supabase ca-central-1）。
目标：每次发布前都能用同一套步骤回答「代码能编译、逻辑没退步、页面在真实设备上可用、
接口与数据边界没有开口、生产环境处于健康状态」。本规范分八层，前四层由 `ship2-v53.command`
门禁自动执行，后四层按本规范手动 / 脚本执行并出报告（`design/test-report-<日期>.md`）。

## 0. 原则

1. **先定规范再测试，测试结果只记事实**：每条用例写清「输入 → 期望 → 实际 → 结论」，不写「大概没问题」。
2. **确定性优先**：能用脚本测的（tsc、vitest、HTTP 探针、SQL 探针、Playwright 量几何）不靠肉眼。
3. **只读探针**：对生产库的探针一律只读或在 `begin … rollback` 事务里跑；不创建长期存在的探针数据。
   审计用的临时账号由 `scripts/mobile-audit.mjs --authed` 自建自删。
4. **一处失败即记录，不阻断其他层**：各层独立，报告里逐层给出 通过 / 失败 / 未执行（原因）。
5. **PII 红线**：报告里不写申请人姓名、证件号、电话；用 screening id 引用。

## 2. 测试层级

### L0 静态检查（门禁）
- `npx tsc --noEmit` 零错误。
- `npm run lint` 零 error（warning 记录不阻断）。
- 通过标准：两者退出码 0。

### L1 单元与模块逻辑（门禁）
- `npm test` 全绿。覆盖对象与守卫文件的对应关系：
  - 筛查评分 `lib/screening/rubric.ts` → `rubricDepth` / `calibrationSalariedProfessional` / `case6269Ash` / `case28KimYi`
  - 取证 `lib/forensics/*` → `forensics*` / `recencyAndLetterQuality` / `employerChecks` / `bureauEmployer`
  - 法庭匹配 `lib/screening/portalMatch.ts` → `portalMatch`
  - 管家 `lib/agent/*` → `prompts` / `guardrail` / `listingSearch*` / `listingPaging` / `commercial`
  - 计费 `lib/billing/*` → `subscriptionState` / `freeWindow`
  - 文案合规 → `complianceCopy` / `sampleNotice` / `disputesSample`
  - 平台守卫 → `reviewGuards` / `review20260919*` / `walkthrough20260922` / `fixList20260922`
- 通过标准：0 failed；新增功能必须带同名 spec。

### L2 构建与产物（门禁）
- next-on-pages 编译成功；`_worker.js` 入口非空；Worker 总大小记录（当前约 9 MB）。
- 通过标准：ship 脚本第 3 步不中止。

### L3 部署后冒烟（门禁）
- `scripts/smoke.sh` 9 探针：首页、安全头、定价、房源、角色页、筛查页、公开分享无效 token、匿名 turn（零持久化 + 模型回退）、续约 turn（行情卡）。
- 通过标准：两次运行都红 = 回滚。

### L4 路由与接口契约（本规范新增，脚本 `scripts/route-audit.mjs`）
- **公开页面**：全部无参路由 + 代表性动态路由，匿名 GET 期望 200；不存在的路径期望 404；`/landlord/settings` 等别名期望 308。
- **重定向与头**：apex → www 308；`Strict-Transport-Security`、`X-Frame-Options: DENY`、`Referrer-Policy` 按路径（`/verify/*` no-referrer）。
- **接口无凭证行为**：受保护接口（screen-score / deep-check / screening DELETE / verify/create / agent/execute / stripe/*）匿名调用期望 401 或 400，绝不能 200 或 500。
- **接口输入校验**：`/api/contact` 空表单 400；`/api/agent/turn` 超长 message 被截断而非 500；`/api/public/stats` 200 且四个数字为非负整数。
- **限流**：匿名 turn 超过每小时 8 条返回 429 + 中文提示。
- 通过标准：每条期望状态码一致；任何 5xx 即失败。

### L5 数据边界（只读 / 回滚事务）
- 匿名 anon key：`listings` 只能读 `is_active AND (verified OR realtor)`；`screenings`、`landlords`、`verification_requests`、`household_invites.token`、`agent_profiles` 整表不可读。
- authenticated（非本人）：读不到他人 screenings / lease_documents。
- 触发器：`guard_listing_trust_fields`（非管理员改 `verification_status` 回 pending）、`guard_paid_fields`（本人改 `plan` 被打回）——在 `begin … rollback` 内验证。
- 数据健康：`screenings` 里 `status='scoring'` 且 `progress.at` 超过 10 分钟的行数（应为 0）；`listings` 里 `is_active=true AND verification_status='pending' AND source='stayloop'` 对匿名不可见；`ltb_orders` / `ca_corp_registry` 最近刷新日期。
- Supabase advisors：security 与 performance 建议清单，逐条判定「修 / 记录」。
- 通过标准：每条断言成立；advisors 里新增的 ERROR 级项必须处理。

### L6 系统适配（Playwright + 内置浏览器）
- **手机几何**：`scripts/mobile-audit.mjs` 与 `--authed`，320 / 390 宽 × zh / en，文档级横向溢出 = 0，被 `overflow:hidden` 裁掉的可交互元素 = 0。
- **水合**：zh 与 en 首屏无 React #418 / #423；控制台无 error 级日志（允许第三方 warning）。
- **表单**：手机断点文本控件字号 ≥ 16px（`tests/mobileForms.spec.ts` 守卫）。
- **无障碍基线**：`<html lang>` 与 `data-lang` 一致；`img` 有 alt（装饰图 alt=""）；按钮有可读文本或 aria-label；页面有且只有一个 h1。用内置浏览器 `javascript_tool` 逐页统计。
- **性能基线**：公开首页 / 定价 / 房源列表 / 筛查页的 TTFB（curl）与 Worker 冷启动；记录，不设硬阈值（Cloudflare 边缘）。
- **浏览器矩阵**：Chromium 自动化；Safari（iOS）与 Firefox 记为「未执行」并在报告里注明。
- 通过标准：溢出 0；控制台 error 0；无障碍基线每页 0 缺陷或有明确记录。

### L7 关键业务流（端到端）
- 匿名：首页管家对话（租客找房 → 房源卡 + 行情卡）；房东 onboarding → 工作台预览；`/apply/[slug]` 表单。
- 登录（审计账号）：发布向导 5 步 → 房源进 pending；筛查上传 → 报告（用 `case 28` 原件回归一次，比较 tier 与硬门槛）；深度核查三家雇主卡；订阅卡状态；设置页。
- 通过标准：每条流程走通，结果与 CLAUDE.md 记录的口径一致（筛查 66 / review / 无门槛；深度核查银行卡片 Bank Act）。

## 3. 报告格式

`design/test-report-<日期>.md`：
1. 摘要表：层级 / 用例数 / 通过 / 失败 / 未执行 / 结论。
2. 逐层明细：用例、期望、实际、证据（命令、状态码、数字、截图路径）。
3. 缺陷清单：编号、严重度（P0 阻断 / P1 主流程 / P2 体验）、复现、修复状态、守卫测试名。
4. 未执行项与原因（工具、权限、成本）。

## 4. 节奏

- 每次部署：L0–L3（自动）。
- 每次涉及界面 / 路由 / 权限的改动：加 L4–L6。
- 每周或每次筛查规则改动：L7 的筛查回归（case 28 原件）。
- 每月：L5 的 advisors 与数据健康。
