## 「找经纪和服务商」统一入口（2026-11-16 · 用户「要设计一个入口，可以所有的角色都可以找到经纪和服务商的页面」→「按建议实现」· ship113–114）

**起因**：用户问租客能不能单独查找经纪和服务商。查下来经纪目录 `/agents` 和专业服务目录 `/providers/professional` 都有，但入口零散（页脚一处、几个场景链接），工作台里没有；维修类服务商只有房东看得到（09-26 定的范围）。先出方案 `design/find-directory-2026-11-16.md`，四处决策点用户都按建议定。

**做了什么**
- 一个栏目三个标签，各是真实地址：经纪 `/agents`、维修服务 `/providers`（新页面）、专业服务 `/providers/professional`。共用标题「找经纪和服务商」+ 标签栏 `components/directory/FindHeader.tsx`，三个页面原来各自的 h1 降成 h2，整个栏目只有一个 h1。
- `/providers`：把房东服务商页里「已核验」那部分拿出来给所有登录身份看。未登录只显示八个工种和登录提示，页面在登录前不发任何数据请求（`provider_directory` 本来就只给 authenticated；上线后用匿名 key 直接请求三张表都是 401）。卡片：名称、工种与覆盖、已核资质与到期日、城市、收费方式、评价均分、邮箱 / 电话 / 网站（网站过 `externalHref`）。按身份多一行提示：租客「先报修」+ 去报修，房东指回服务商管理页，服务商指向入驻资料，经纪没有。排序在 `lib/marketplace/directory.ts`（资质齐全在前 → 核验时间早的在前 → 名称），规则写在页面上。
- 经纪标签：`/api/agents` 多返回 `basic`——RECO 核验有效但没开公开主页的经纪，只有注册名 / 类别 / 经纪公司 / RECO 号 / 核验日（`toBasicAgent`，没有 slug、auth id、简介、照片、联系方式）。带筛选条件时不返回（它们没有可匹配的语言 / 专长 / 区域）。卡片不是链接。
- 入口：工作台侧栏「找人」（`FIND_ITEM`，租客 / 房东 / 经纪三个身份，紧跟「消息」，新图标）；头像菜单「找经纪 · 服务商」（消息下面）；页脚原「找经纪」改字（key 与地址不变）；`/services` 首屏加按钮「看看有哪些服务商」；租客维修页一行；服务商工单页一行「我在目录里的样子」。页头那一排没动。
- `/services` 的现状说明原写「入驻信息只在房东派单时可见」，改成「服务商和联系方式要登录后才看得到；派单只有房东能做」。
- 名字以 `[TEST]` 开头的行标「测试数据」（`isTestName`）。

**和方案不一样的地方**：服务商身份没有工作台侧栏（它的页面用普通页头），所以侧栏入口只有三个身份，服务商走头像菜单与工单页链接；租客提示把「费用不该由你出」改成「正常使用坏掉的也不该由你出钱」（租客自己弄坏的不在此列）；手机「更多」里那一组的组名改成「消息 · 找人」。

**上线后发现并修掉的一处**：标签栏用了 `overflow-x-auto` + 链接 `-mb-px`，负边距让标签栏竖向多出 1px，手机上右侧出现一条滚动条。去掉负边距、加 `overflow-y-hidden`（ship114）。
