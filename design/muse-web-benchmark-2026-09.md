# Muse 网页版 UI/UX 对照 → Stayloop 网页端助手页可否照此改（2026-09-24）

研究对象：Muse from Meta 的**网页版**（muse.ai，已登录状态）。来源：用户 2026-09-24 提供的一张桌面截图（约 1900px 宽，
Chrome）。手机端的对照研究见 `muse-mobile-benchmark-2026-09.md`（已于 09-22 落地）；本文只看网页端的**版式**，不看它做的事。

结论先说：**可以改，而且比现在更贴合用户 09-24 定下的方向（AI-native、对话为主、头像居中名字在下、三角色一致）。**
它是一次「重新摆放」而不是重做——三块内容 Stayloop 都已经有了，只是位置不对：活动日志现在藏在手机端点头像的弹层里，
待办 / 想法 / 进度三页只在手机底栏能到，桌面右栏堆的是仪表盘卡片。

---

## 1. Muse 网页版长什么样（一张截图的逐元素清单）

三栏，从左到右：

| 区块 | 宽度（约） | 内容 | 备注 |
|---|---|---|---|
| **图标窄栏** | 64px，深色 | 自上而下：对话 · 搜索 · 文件 · 想法（灯泡）· 任务（勾）· 连接的应用（四格）；下方用户头像；底部「安装到桌面」与汉堡 | **没有文字标签**；当前项高亮 |
| **对话** | 其余全部（约 1560px） | 顶部左「☰ Chats」胶囊（打开对话列表）、右「Invite」；消息流：助手消息是深灰圆角块、左对齐、**旁边没有头像**；用户消息淡一些；附件是「预览缩略图 + 文件条」两段卡；悬停出现 表情 / 回复 / 复制 三个小动作；底部一条**宽圆角输入条**「+ · Message · 🎙」，最大宽约 800px 居中 | 消息列宽约 620px，不铺满 1560px；对话**没有卡片边框**，就是页面本身 |
| **助手面板** | 380px，深色 | 右上 ×；**居中大头像**（3D 形象）+ 右下角铅笔（改头像/名字）；名字 **Ashley**；绿点「Connected」；一排 4 个图标的分段控件（清单 / 已完成 / 时钟 / 更多）；活动日志按 **Today / Yesterday** 分组，每条 = 图标 + 粗体标题 + 一句说明 + 时间 | 可关闭；这是助手的「身份 + 它做过什么」，不是仪表盘 |

视觉：深色主题、单一强调色、圆角大、留白多、没有 KPI 数字。

## 2. 与 Stayloop 网页端（2026-09-24 晚版）逐项对照

| Muse | Stayloop 现状（`/x/agent`，md+） | 差距 |
|---|---|---|
| 64px 图标窄栏 | 220px 深色侧栏，图标 + 文字标签（09-05 学 Flinks 控制台的决定） | 对话少了约 160px；Muse 的窄栏把「待办 / 想法 / 进度」放在导航里，我们这三页只在手机底栏 |
| 对话 = 页面本身，无边框 | 对话在一张白卡里（圆角 + 边框 + 阴影），卡片顶部是头像 + 名字 + 状态行 | 我们多一层「卡」；头像占了对话顶部 |
| 助手消息旁没有头像 | 每条助手消息左边一个小圆球 | Muse 把身份放在右面板，消息流更干净 |
| 宽圆角输入条，居中，约 800px | 输入条铺满卡片宽度，圆角小；模型选择器在输入框下一行 | 形态不同 |
| 审批 / 产物在对话里 | 手机端审批卡在对话末尾（compact）；桌面端审批卡在**右栏** `PendingActionsPanel`（lg+） | 桌面端与手机不一致 |
| 右面板 = 头像 + 名字 + 状态 + 活动日志，可关闭 | 右栏 = 待批 / 状态总览瓦片 / 当前进度 / 推荐 / 记忆 / 相关页面，六张卡，不可关闭 | 我们的右栏是仪表盘；活动日志只在手机点头像的弹层里（`ActivitySheet`） |
| 活动日志按 今天 / 昨天 分组，每条带图标与时间 | `ActivitySheet`：最近 20 条，一列，时间在右 | 只差分组与图标 |
| 「Chats」多对话列表、「Invite」 | 每角色一条线程；无邀请 | 不采用 |

## 3. 建议采用（A–F）

- **A · 图标窄栏（64px）取代 220px 文字侧栏（md+ 全部工作台页）**：图标沿用现有 `Rail` 的图标，文字改为悬停提示 + 当前项右侧小标签；
  顶部角色头像 + 角色名，底部设置。**新增三项：待办（带待批数红点）· 想法 · 进度**——与手机底栏一致，桌面端终于能到这三页。
  代价：09-05 定的「带文字标签的 Flinks 式侧栏」在桌面端改成图标式；导航可发现性靠悬停提示。
- **B · 对话即页面**：`/x/agent` 桌面端去掉对话外层的卡片边框，消息列限宽 760px 居左中；助手消息不再每条带小圆球
  （身份在右面板）；输入条改为居中的宽胶囊（+ · 输入 · 🎙 · ↑），模型选择器收进 + 菜单或输入条右侧小字。
  对话顶部**什么都不放**（09-24 已定：不再把今日卡 / 进度条放对话上方）。
- **C · 右面板改成「助手面板」**（360px，可关闭，记住状态）：居中头像（72px，可点改名 → 现有起名页）+ 名字 + 状态行
  （沿用现有 `statusLine`：空闲 / 正在… / 等你点头 N 件）+ 三段控件 **活动 · 待办 · 记忆**：
  活动 = `ActivitySheet` 的数据按 今天 / 昨天 / 更早 分组、每条带动作图标与时间、底部「完整审计 →」；
  待办 = 待批卡的一行摘要 + 「去待办页」；记忆 = 现有 `PrivateMemorySnapshot`（可编辑）。
  关闭后对话铺满，右上角留一个小头像按钮可重新打开。
- **D · 审批卡进对话流（桌面端也是）**：与手机一致，卡片排在线程末尾，决定后折叠成一行；`PendingActionsPanel` 不再在右栏。
- **E · 现在右栏的六张卡各归其位**：状态总览 + 当前进度 → `/x/progress`（已有）；推荐 → `/x/ideas`（已有 `buildIdeas`，
  可把 `RecommendationDeck` 挂进去）；记忆 → 面板「记忆」段 + `/x/progress`；相关页面 → 窄栏本身。
- **F · 三角色完全同构**：三页只差角色、名字、颜色；`WorkspaceShell` 出一个 `variant="assistant"` 承担 B/C/D，三页各 30 行。

## 4. 不抄

- 深色主题（配色是 09-05 用户定的 Flinks 蓝白系；深色只保留侧栏 / 窄栏）。
- 「Chats」多对话列表（每角色一条线程是既定架构，记忆与审批都挂在它上面）。
- 「Invite」、3D 形象头像、Secure VM / 代操作网页、购物卡（手机研究里已排除）。
- 每条消息的表情 / 回复动作（对话不是聊天室）；「复制」可以有。

## 5. 需要拍板的三点

1. **窄栏（A）**：桌面工作台全部页面改成 64px 图标栏，还是只有助手页用窄栏、其他页保留文字侧栏？
   建议**全部改**——两种侧栏来回切换会跳；悬停提示 + 当前项标签足够可发现。
2. **面板默认开还是关**：建议**默认开**（Muse 也默认开）、可关且记住；首次访问看到头像 + 名字 + 它做过什么，这是「AI-native」的第一印象。
3. **面板宽度**：360px（对话在 1440px 屏上仍有约 1000px）。
