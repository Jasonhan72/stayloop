Blueprint · 消息与沟通 · 2026-09-29

消息与沟通系统重设计

目标：所有角色——租客、房东、经纪、服务商，以及 Stayloop——围绕同一件租房的事无障碍沟通。站内、邮件、短信三个渠道进同一份记录；每条都有服务器时间戳、任何人都删不掉，将来可以直接作为争议证据。有一个独立入口，随时可以发起新消息。

1 · 现在有什么，缺什么

节点 4（2026-09-26）已经打下的底子不推翻，在上面加。

已经有的 保留

  • 每件事一条对话：在管租约、申请、维修工单（租客 · 房东 · 服务商三方）
  • 只追加：谁都改不了消息，客户端删不掉；撤回 = 新增一行，原文保留
  • 服务器时间 + 发送者在该事务里的身份 + 当时的帽子
  • 附件由服务器算 SHA-256，客户端伪造不了
  • 三种回执：已送达 · 已打开 · 已确认收到
  • 正式通知在对话里留副本（进入通知、决定通知、续约函）
  • 事务证据包导出（带内容指纹）

缺口 这次要补

  1. 没有「新消息」入口：只能在各事务页面里发，消息页只能看、不能发起
  2. 覆盖不全：经纪和服务商没有消息页；房源咨询 / 看房请求走待办卡 + 邮件，不进对话；经纪和客户之间没有对话；没有「联系 Stayloop」
  3. 渠道单一：对方收到的只是提醒，回邮件不会进记录；没有短信
  4. 证据还能更硬：服务端仍能删消息；没有哈希链，证明「没被删改过」只能靠我们自己说
  5. 8 秒轮询，不是实时

2 · 五条原则

  1. 每段对话都挂在一件租房的事上房源、申请、租约、维修工单、经纪委托、争议。不做脱离事务的私聊——谁能和谁说话，由这件事里的关系决定；证据也因此有上下文。
  2. 一份记录，多个渠道站内是正本；邮件和短信只是投递与回复的通道，对方直接回邮件、回短信，都自动进同一份记录。
  3. 中转，不交换私人联系方式双方默认看不到彼此的私人邮箱和手机号，都经 Stayloop 转发——既保护隐私，也保证每一次往来都被记下。
  4. 证据级记录只追加、服务器时间、身份与验证方式、哈希链、逐渠道回执、原始邮件 / 短信存档、可导出、第三方可复核。
  5. 消息不等于法定送达N 表等正式通知仍按 RTA s.191 与标准租约里的电子送达同意执行；平台消息是沟通记录，也是「已送达 / 已读」的佐证。

5 · 证据模型

要证明什么怎么做到现状
什么时候数据库写入时盖服务器时间（UTC），界面显示多伦多时间；客户端时间一律不采信。已有
是谁站内 = 登录会话；邮件回复 = 专属回复地址（签名令牌）且发件地址与档案一致；短信 = 已验证的手机号。每条记录写明验证方式。补邮件 / 短信
没被删改数据库层对所有人禁止修改和删除消息——包括 Stayloop 后台与数据库管理账号；删对话、删事务都不会连带删消息。更正 / 撤回 = 新增一条，原文保留。补：服务端也不能删
一条都没少哈希链：每条消息的指纹 = SHA-256（上一条指纹 + 本条内容）。删掉或改动任何一条，后面的链都对不上；导出时附每条指纹和校验结果，第三方可以自己复算。新
对方收到了逐渠道回执：已发出 · 已送达 · 已打开 · 已读 · 已确认收到，各带时间；邮件和短信保存服务商的消息编号。补邮件 / 短信
原件入站邮件保存原始 MIME 及其 SHA-256；短信保存服务商回调原文；附件已有指纹。新
拿得出来事务证据包：PDF（给人看）+ JSON（给机器复核），含全部消息、回执、附件指纹、哈希链校验结果、生成时间与生成人。已有，升级
为什么这样做（供理解，不是法律意见）　安省《证据法》s.34.1：电子记录能否被采纳，关键在于能证明「记录它的系统是完整的」——所以要在系统层面做到只追加、服务器时间、哈希链、可复核的导出。LTB 依《法定权力程序法》s.15 可以接收任何相关证据。

6 · 技术方案（给你参考）

数据

  • 对话类型增加：房源咨询、经纪委托、联系 Stayloop
  • 新表：对话参与方（含没账号的人的邮箱 / 手机与回复令牌）、逐渠道回执、入站原始件
  • 消息增加：渠道、上一条指纹、本条指纹（写入时由数据库计算，同一对话串行）
  • 删除保护对所有角色生效；对话、事务删除不连带消息
  • 看房请求 / 提问从待办卡搬进「房源咨询」对话，待办卡只做提醒

渠道

  • 站内：Supabase Realtime 按行级权限推送，替代 8 秒轮询
  • 邮件发出：沿用 Resend
  • 邮件收回：Cloudflare 邮件路由 + Email Worker（免费），只用子域名 reply.stayloop.ai，主域名收信不动
  • 短信：Twilio 加拿大号码；手机号验证码验证 + 记录同意；回 STOP 退订；回调入档
  • 推送：沿用现有 Web Push

建议：用 Twilio，上限先定每月 US$30。
2 · 邮件回复用 reply.stayloop.ai 收？在 Cloudflare 给这个子域名加收信记录（免费），主域名 stayloop.ai 的收信不受影响。
建议：可以。
3 · 记录保留多久？事务结束后仍保留，用作争议证据。账户注销时删个人资料，但对话记录保留（对方也有证据权益），隐私页写明。
建议：事务结束后 7 年（覆盖 LTB 一年、小额法庭两年的时效，并与税务记录一致）。
4 · 默认不交换私人联系方式？双方只通过 Stayloop 的中转地址 / 号码联系，除非自己在对话里写出来。
建议：是。
