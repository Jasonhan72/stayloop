# 「找经纪和服务商」的统一入口 · 设计方案（2026-11-16，已定稿并实现）

起因：用户问「租客能不能单独查找经纪和服务商」，查下来经纪有目录页、专业服务有目录页，但入口零散，维修类服务商对租客不开放。用户要求：**设计一个入口，所有角色都能找到经纪和服务商的页面。**

**2026-11-16 定稿**：用户「按建议实现」，第 6 节四处都按建议定。当天实现，见文末「实现记录」。

## 1. 现状

| 找什么 | 页面 | 谁能看 | 入口在哪 | 问题 |
|---|---|---|---|---|
| 经纪 | `/agents` 目录 + `/agents/[slug]` 主页 | 所有人，免登录 | 页脚「找经纪」、房源页「查看经纪主页」 | 工作台里没有入口；只列自己开了公开主页的经纪，现在只有 1 位（测试号），另外 2 位已核验的不出现 |
| 专业服务（Paralegal / 律师 / 保险经纪 / 房源摄影） | `/providers/professional` | 登录后任一身份 | 房东的服务商页、入住清单的保险项、欠租提示里的 Paralegal 链接 | 没有导航入口，租客和经纪基本找不到 |
| 维修服务商（水管 / 电气 / 供暖 / 电器 / 虫害 / 门窗 / 门锁 / 杂工清洁） | 只有房东的 `/landlord/providers` | 房东 | 房东侧栏「服务商」 | 租客、经纪看不到；09-26 定过「不做公开服务商目录」 |

数据库这边其实已经允许：`provider_directory` 视图对所有登录账号可读（匿名不可读），`agent_directory` 匿名可读。所以这次主要是页面和入口的事，不需要放宽数据权限。

## 2. 方案一句话

**一个栏目「找人」，三个标签：经纪 · 维修服务 · 专业服务。四种身份的工作台侧栏、头像菜单、页脚都有同一个入口，点进去是同一个页面。**

三个标签各是一个真实地址，共用同一个标题和标签栏：

| 标签 | 地址 | 说明 |
|---|---|---|
| 经纪 | `/agents` | 现有页面，加上共用的标签栏 |
| 维修服务 | `/providers` | **新页面**，把房东服务商页里「平台已核验的服务商」那部分拿出来给所有登录身份看 |
| 专业服务 | `/providers/professional` | 现有页面，加上共用的标签栏 |

这样做的好处：现有地址、分享出去的链接、路由审计和守卫都不用改；经纪目录继续免登录、能被搜索引擎收录。

## 3. 入口放在哪

| 位置 | 谁看得到 | 做法 |
|---|---|---|
| 工作台侧栏 | 租客、房东、经纪、服务商，登录后 | 四个身份都加一项「找人」，放在「消息」下面。悬停说明：「找经纪、维修服务商和专业服务」。手机上进「更多」 |
| 头像菜单 | 所有登录用户，任何页面 | 「消息」下面加一行「找经纪 · 服务商」 |
| 页脚 | 所有人，含未登录 | 现有的「找经纪」改成「找经纪 · 服务商」 |
| 「维修与服务网络」页 `/services` | 所有人 | 首屏加一个按钮「看看有哪些服务商」 |
| 场景里的链接 | 按场景 | 现有的都保留（房源页、入住清单保险项、欠租提示里的 Paralegal）；租客维修页加一行「想找专业服务？」 |

**页头那一排不动。** 「我是▾ · 产品 · 房源 · 定价 · 租客筛查」是定过的，位置不变；入口放进头像菜单和侧栏，登录后在任何页面都是两次点击以内。

房东侧栏原来的「服务商」（`/landlord/providers`）保留：那是房东管理自己的联系人、派单策略和工单记录的地方，跟「浏览目录」不是一回事。目录页上给房东一行「管理我的服务商与派单策略 →」。

## 4. 页面长什么样

共用的页头：标题「找经纪和服务商」，一句说明「Stayloop 只做展示与转介，不抽成，费用由你和对方直接谈」，下面是三个标签。

**经纪标签**（`/agents`，免登录）
- 筛选：语言、专长、服务区域（现有）。
- 卡片：头像、注册名、经纪公司、类别、RECO 核验徽章、语言与区域、在租房源数（经纪选择公开时）。
- 点卡片进经纪主页；联系要登录，经平台发消息，不显示双方邮箱电话（现有做法）。

**维修服务标签**（`/providers`，新）
- 未登录：能看到八个工种和「登录后可以看到服务商与联系方式」，不显示任何服务商。匿名权限不放开。
- 登录后：按工种、城市筛选；卡片显示名称、工种、服务城市、资质徽章（牌照 / 保险 / WSIB，带到期状态）、收费方式、评价均分。
- 试点范围写在页头：「试点 · 多伦多及周边」。
- 按身份多一行提示，其余内容一样：
  - 租客：「租的房子里东西坏了，先报修。维修由房东负责安排，费用不该由你出。」+ 按钮「去报修」。
  - 房东：「派单在维修页；这里只是浏览。」+「管理我的服务商与派单策略 →」。
  - 经纪：不加提示。
  - 服务商：「这是你在目录里的样子。」+「更新入驻资料 →」。

**专业服务标签**（`/providers/professional`，现有）
- 四个类别：持牌 Paralegal、律师、保险经纪、房源摄影 / 户型图。
- 保留现有的「只展示与转介，平台不派单」说明。

三个标签都没有数据时写实话：「这个类别暂时还没有入驻的服务商」，不放示例数据充数。

## 5. 权限与合规

- 不新增匿名可读的数据。维修与专业服务的联系方式仍然要登录才看得到。09-26「不做公开服务商目录」对未登录访客继续成立；变的是「登录后的租客和经纪也能看」。
- 租客在目录里只能看和直接联系，不能派单、不能建工单。派单仍然只有房东能做。
- 目录不排名、不推荐、不抽成；排序固定（资质齐全在前，其次按入驻时间），页面上写明排序规则。
- 经纪卡片继续醒目显示注册名、类别、经纪公司，以及「Stayloop 不是经纪公司」。
- 外省：这一栏不写任何安省法条；租客那句报修提示也不引条文，所有省份通用。

## 9. 实现记录（2026-11-16）

按方案做完，和方案不一样的地方只有这几处：

- **服务商身份没有工作台侧栏**（服务商页面用的是普通页头，不是工作台外壳），所以侧栏的「找人」只加在租客、房东、经纪三个身份上；服务商从头像菜单进，另外在工单页标题下加了一个链接「我在目录里的样子」。
- **租客那句提示改了半句**：「租的房子里东西坏了，先报修。维修由房东负责安排，正常使用坏掉的也不该由你出钱。」原句「费用不该由你出」说得太满，租客自己弄坏的不在此列。
- **测试数据加了标签**：名字以 `[TEST]` 开头的经纪和服务商，卡片上多一个「测试数据」小标签。现在目录里的 3 家服务商和 2 位经纪都是测试数据，真实的只有 1 位经纪。
- **手机上**「找人」在「更多」里和「消息」同一组，组名改成「消息 · 找人」。
- **`/services` 的一句现状说明跟着改了**：原来写「入驻信息只在房东派单时可见」，现在是「服务商和联系方式要登录后才看得到；派单只有房东能做」。
- 未登录点「去登录」会带上 `?next=`，登录后回到原来的标签。

代码位置：共用标题与标签栏 `components/directory/FindHeader.tsx`；维修服务页 `app/providers/page.tsx`，排序规则 `lib/marketplace/directory.ts`；经纪基本信息 `lib/agentPublic.ts`（`toBasicAgent`）与 `/api/agents` 的 `basic` 字段；侧栏 `components/workspace/rail.tsx`（`FIND_ITEM`）；守卫 `tests/findDirectory20261116.spec.tsx`。没有数据库迁移。
