01 · 产品定位与技术架构

Stayloop 是面向安省（Ontario）租房市场的 AI 平台。它不是「按份出售筛查报告」的工具，而是把租客、房东、经纪三方的整个租房过程放进同一条对话里：找房、看房、申请、筛查、录取、签约、在管、续约。每一个会对外产生影响的动作（发邮件、发租约、发续约函）都由 AI 提议、由人批准、批准后才执行，并且全部留痕。

三条原则贯穿全站：① 提议而不决定（propose, don't decide）；② 数字来自确定性代码而不是模型（评分、信用分析、规则检查全部可复算）；③ 合规写在代码里（安省 RTA、OHRC 租房政策、《消费者报告法》的规则是单一来源，页面、助手、API 引用同一份）。

02 · 三种身份与工作台

一个账号可以同时拥有三顶「帽子」：租客（所有人都有）、房东（有房东档案即得）、经纪（提交 RECO 注册资料并经人工核验）。当前身份由路由前缀决定，右上角头像菜单可切换；权限永远只看帽子与数据归属，不看界面状态。

TENANT · LUNA租客工作台找房对话、我的申请与看房、租客护照（分享链接 + API 授权）、租约与在管租约、报修、审计记录。
LANDLORD · LOGIC房东工作台房源发布与管理、申请人审查、租客筛查、租约起草与电子签、在管租约与租金记录、续约触点、财务（样例）、审计记录。
AGENT · BRIEF经纪工作台RECO 认证、替房东客户筛查的交接、挂牌定价（实时挂牌 + TRREB 基准）、带看准备包、租约与押金事实、合规边界。

手机端（<768px）采用五栏底部导航：助手 · 待办 · 想法 · 进度 · 更多。待办页列出所有等你批准的卡片（红点计数）；想法页由纯函数从待办、画像与当前阶段拼出「我可以替你做的事」；进度页显示流程阶段、活数据瓦片与可编辑的记忆。桌面端保留深色侧栏。跨身份守卫：不能向自己的房源提交申请或看房意向（数据库触发器拦截）；经纪未认证时经纪专属页只显示认证入口。

03 · AI 助手（Luna / Logic / Brief）

首页本身就是助手：匿名访客可直接对话（真实房源、真实行情，按 IP 限次、不落库）。登录后进入角色工作台，助手具备：

  • 推理与记忆：每轮由服务端模型推理，客户端按 RLS 写入记忆（偏好 / 画像 / 约束）与审计事件；每用户每角色约 20 小时一次「反思」，把最近对话与批准 / 拒绝记录整合成结构化画像，下一轮注入（禁止推断任何受保护特征）。
  • 合规守卫：每轮输出经确定性过滤——拦截基于 OHRC 受保护特征的拒绝、标记违法租约条款、剥掉「已经办好」的虚假声明、降级越权范围；命中写入 compliance_events。
  • 找房：先查 Stayloop 自有房源，再用 Realtor.ca 实时补足到 6 套一页，附实时行情样本与 TRREB 官方季度基准；「换一批」翻页或带排除集重搜。隐藏技能：商业 / 工业场地检索（厂房、仓库、店面、写字楼），按面积 / 净高 / 用途 / 禁止用途分层匹配并出横向对比表。
  • 发房源：一句话生成房源草稿卡，同时一次问完缺项（面积 / 宠物 / 吸烟 / 租期 / 水电网 / 车位 / 家具）；文案只写用户给过的事实，未确认的说法会被删掉。
  • 续约 / 涨租谈判专线（租客）：引用真实租约条款 + 安省法规事实包 + 行情卡，按五段结构回答，可起草给房东的回信（作为待批卡）。
  • 审批脊柱：助手提出的每个动作都是一张待批卡（收件人、数据范围、排除数据、风险等级）。房东可先「预览正文」看到将要发送的标题与正文；批准后有 60 秒撤销窗口，撤销即回到待批并写审计；执行器只信数据库里的事实（租约行、申请行），不信卡片元数据里的收件人。

04 · 租客筛查（核心模块）

房东把申请人自愿提交的材料上传（证件、工资单 / 在职信、征信报告、银行流水、申请表、推荐信；单文件 ≤ 25 MB，大图自动压缩，超大 PDF 在浏览器内转页图），几分钟出报告。管线分层，数字一律来自确定性代码：

层内容
抽取模型按文件类型抽取事实（收入、雇主、征信 tradeline、证件、申请表）；扫描件走 OCR（预算按页数，失败回退第二路 OCR）
文件取证PDF 元数据与生成器指纹、增量修改痕迹、银行 / 工资系统排版引擎识别、统计法扣缴复算、生成器签名、时效（每份文件自己的 as-of 日期）、证件有效期、信件质量（拼写、电话不一致）、跨文档一致性（收入互证 ≤3% 才算吻合、居住时间线 vs 加拿大足迹、自任房东）
工资流水深读识别代发商（ADP / Ceridian / OSV 等）、入账 = 净薪、奖金三方对账、月初房租形态支出、NSF、发薪日贷款、博彩、催收、国际汇款、最低余额折算租金月数
信用分析五档分数、DTI、循环利用率（分期与按揭不计）、逾期三信号、硬 / 软查询按 12 个月、催收机构查询、直接读征信文本补漏转录的逾期日期；征信档雇主 ≠ 在职信雇主时先找原因（信贷事件早于入职 = 必然过时，不是矛盾）
公开记录安省法院门户按申请人与共同申请人实查（各字序 + 模糊，全部执行后合并，强匹配且为被告方才进硬门槛；403 时经加拿大数据库中转）；LTB 判令开放数据目录自建索引（只有房东发起且对方是租客才算风险；同名须地址佐证；目录无结果字段，只写「已出判令」）；CanLII 只作披露。房东、经纪、HR 签署人永远不是筛查对象。
一致性审查模型逐文件交叉核对 + 确定性后闸（生日格式、旧址 vs 现址、已结清账户、职称同义词、o/a 商号、韩国虚岁等「措辞 ≠ 矛盾」全部丢弃或降级）
评分表五个维度（付款能力 / 信用 / 租务 / 核验 / 沟通）+ 硬门槛 + 档位（通过 / 复核 / 附条件 / 拒绝）。收入租金比只加分不扣分、薄档案不扣分（OHRC）；纸面互证与第三方核验分开计价（无任何外部核验时核验维度封顶）；取证严重度不再把「披露」当证据累加，累加到疑似伪造必须有 high 级以上项。
报告结果页、完整报告页（已核验事实 / 推断分栏、逐文件「房东解读」与建议追问、信用分析看板、法庭与 LTB 收录范围条）、可打印 PDF、雷达图、申请人通知信（s.10(7) + AI 辅助 / 房东本人决定声明）。报告到处标「仅供参考 · 非拒绝依据」。
深度核查每家雇主：注册库状态（注销即红色「不可能在发工资」并去 Ontario Gazette 找注销原因）、入职日期 vs 成立日期、域名注册日期（RDAP）、联系邮箱是否个人邮箱、地址 / 区号、雇主诉讼、董事 / 签署人与申请方成员是否同一人（注册库不公开董事时读公司网页）、《银行法》附表银行直接识别、商号折进注册实体
管理免费档每月 5 次；筛查记录可删除（连同文件与核验请求，也是申请人数据删除请求的执行路径）；卡死行自动标错误
校准方法：每个真实案例都由人工逐份读原件与模块报告对照，模块漏掉的一律系统化成确定性规则并加守卫测试（2026-09 已做 5 个案例：受薪专业人士、双申请人、伪造在职信、注册库非活跃雇主、装修工程等）。同一份原件多次重跑的抽取抖动是最重要的教训——评分层每条硬规则都必须能承受抽取抖动。

05 · 房源：发布、浏览、看房与申请

  • 发布：五步向导（基本信息 → 真实照片，至少 1 张 → 价格 + 条件：租期 / 宠物 / 吸烟 / 家具 / 租金包含 → 配套 → 发布前检查）；或在对话里一句话生成草稿卡。发布前检查只列确定性项：押金 ≤ 一个月、无禁宠条款、无申请费 / 宠物押金、无 AI 补写、有照片。没有照片的房源不会被创建，也不会出现在任何公开页面。
  • 可见性（数据库强制）：房东自发房源先 pending，管理员核验后公开；Realtor.ca 导入的行带来源徽章直接可见；房源核验后改地址 / 租金会自动打回待核验。
  • 房源页：画廊、生活配套（吸烟 / 租期 / 水电 chip）、「入住前费用一览」（首月 + 租金押金 + 钥匙押金，押金超一个月标红并引 RTA s.106，划掉安省不允许的申请费 / 宠物押金 / 清洁押金）、认证经纪目录（租客自选、直接联系，Stayloop 不派单不收费）、房东为持牌经纪时的 TRESA 披露标记。
  • 看房与提问：登录租客提交看房意向或提问 → 房东助手上出现一张待批卡 → 批准后发信确认；租客在「我的申请」页看到真实记录。
  • 申请：公开申请表（匿名可提交，每房源限流，材料传入受保护桶）；申请人登录后可看到自己的申请与房东的决定。

06 · 租房全流程闭环

从房源到续约的每一步都有真实后端并可在生产上跑通（2026-09-23 三角色端到端模拟已验证）：

#环节实现
1房源发布 → 核验向导 / 对话草稿 → 管理员队列 → 公开页
2看房 / 提问意向行 + 房东待批卡 → 预览 → 批准 → 邮件

5决定通知录取 / 补材料 / 婉拒 → 待批卡 → 邮件固定带 s.10(7) 与 OHRC 声明 → 申请状态与合规事件落库

07 · 租约、电子签与在管租约

  • 租约草稿：安省标准租约（2229E，2020-12 版）为默认；TRREB Form 400 只作要约。附加条款保存前检查：禁宠条款、额外费用 / 押金、押金超一个月、禁装空调条款（2026-07 起无效）一律阻止。
  • 电子签：租客凭签署链接无需账号签署；房东回签后租约「已双签」，链接长期有效可查看下载。守卫触发器：发送后条款冻结、客户端不能伪造签名或状态。
  • 在管租约（households）：任意角色可导入已签租约（AI 抽取 → 人工确认），邀请对方加入；对方接受后才算「已确认」，未确认的记录不进任何公开面。共享中心 /h/<id>：概览 / 对话 / 租金记录 / 报修。
  • 租金记录：只记录与提醒，不经手资金；按 2026-09-21 起的法定定义自动标注「持续迟付」（6 个月内 3 次在到期日 7 天后才付），只提示不代发通知。

09 · 租客护照与本人授权核验

  • 护照分享链接：租客生成只读链接给站外房东，可撤销，每次访问留痕；可勾选允许第三方通过 API 读取的范围（身份 / 银行 / 征信 / 租史），每次读取通知租客。租史只认对方确认的在管租约或双签租约。
  • 本人授权核验：房东在筛查记录上生成核验链接；申请人先签版本化同意（目的 / 内容 / 谁看 / 保留 / 撤回），再逐步授权：身份（Veriff 托管）、银行（Flinks Connect，只存确定性摘要：掩码账号、持有人、循环入账、月薪估计、NSF 次数）、征信（Equifax，不收 SIN）。核验结果确定性覆盖评分表的收入佐证与身份维度，报告单列「已核验事实 · 非模型推断」。沙箱结果不进评分。

10 · 经纪认证（RECO）

经纪在 /agent/verify 填注册姓名、RECO 注册号、类别、经纪公司、到期日与业务联系方式（不传证件、不收 SIN）。Stayloop 工作人员在后台手动对照 RECO 公开注册库核验（注册库禁止抓取，永不自动查询）。徽章只表示「核验日在 RECO 注册库上处于注册状态」，链到注册库与投诉入口；展示一律用注册名与经纪公司名。持牌经纪以房东或租客身份交易前弹 TRESA s.32 注册人披露并记录。Stayloop 不做经纪业务、不收佣金或转介费（转介佣金引擎冻结待律师意见）。

12 · Trust API（核验 API）

定位是「安省租房核验 API」，只有真实后端的三个端点，Base URL 与本站同源（www.stayloop.ai/api/v1），密钥由 Stayloop 发放（只存哈希，后台可停用、可绑定房东账号）：

端点说明
POST /listings/compliance免费、无需密钥；对房源字段跑确定性规则（押金上限、钥匙押金、禁宠条款、禁止费用），返回规则编号与法条；不接受、不存储个人信息
POST /passport/verify申请人主动出示：合作方传申请人分享链接里的 token，只返回申请人勾选范围内的结论（身份 / 银行 / 征信档位 / 已确认租史），不返回文件；每次调用审计并推送通知申请人
POST /screen密钥绑定的房东账号名下发起筛查：必须附申请人对同意文本的接受记录，文件从合作方 https 地址抓入受保护桶，立即返回 202，完成后 POST 到 webhook；同一条管线、同样的配额与合规规则
边界写在响应里：Stayloop 不是《消费者报告法》意义上的报告机构；分数与档位是房东自行决定的参考信息，不是拒绝依据；面向金融机构的用途待法律意见。

13 · 通知：邮件、Web Push 与 PWA

  • PWA：可安装到主屏（图标为 Stayloop.AI 字标），Service Worker 不缓存页面（部署即生效），只承担推送。

17 · 数据、安全与隐私

  • 数据驻加：数据库与存储在 AWS 加拿大区；AI 服务商所在地（美国；扫描件 OCR 回退在中国大陆）与检索中转在隐私页如实披露。
  • 访问控制：全部表启用 RLS（事件触发器保证新表自动开启）；付费 / 信任字段、租约签名、在管租约确认等由守卫触发器保护，客户端直写无法绕过；SECURITY DEFINER 函数对匿名撤销执行权；匿名面有全局成本闸。
  • 审计：每次提议、批准、拒绝、撤销、执行、护照访问、Trust API 调用、记忆编辑都写审计事件，租客与房东各有审计页。
  • 申请人权利：通知信写明 60 天内可索取信息性质与来源；筛查记录删除即删除文件与核验请求；护照 token 可随时撤销。
  • 发布门禁：类型检查、826 项测试、构建、线上冒烟、65 条路由与接口契约审计全部内置在部署脚本。
