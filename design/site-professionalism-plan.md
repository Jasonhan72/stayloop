# 全站专业化与用户增长方案(2026-08-12)

> 依据:生产数据 + 全站页面盘点。原则:方案只解决数据证明存在的问题,不做臆想优化。

## 0. 决定优先级的五个数字(2026-08-12 生产实测)

| 指标 | 值 | 含义 |
|---|---|---|
| 注册用户 | 102(近 30 天 +33) | **获客是通的**——没花钱也有稳定注册流 |
| 近 30 天筛查 | 24 单,来自 **3 个房东** | **激活是断的**——33 个新用户里 ~30 个没做过一单筛查 |
| 公开房源 | **7 套** | 房源市场看起来是「死的」,反而伤信任 |
| households | 0 | 在管租约刚上线,还没接进任何漏斗 |
| Agent 事件(30 天) | 257 | Agent 有真实使用,但集中在少数人 |

**核心诊断:问题不在流量,在注册后的第一分钟。** 33 人/月进门,绝大多数没碰到产品的「啊哈时刻」(一份筛查报告)就流失了。同时,登录后的世界里大量页面渲染的是 demo канon 数据(Unit 1207 / Sarah Wang)——真实新用户看到假数据,既困惑又显得不专业。

## P0 — 激活漏斗(最高杠杆,先做)

### 1. 注册后的第一分钟:一条路,不是一张地图
现状:登录 → 角色 agent 页(demo 味最重的界面)。多屏 onboarding(welcome/name/meet/tier1)是设计对齐的遗留争议项。
改法:房东注册后直接落到**筛查引导**(「上传第一位申请人的材料」),租客落到护照,一屏搞定角色+目标;砍掉多余 onboarding 屏。北极星指标:**注册→首单筛查的转化率**(当前约 1/10,目标 1/3)。

### 2. 杀死 demo 数据混淆(专业感的最大伤口)
现状:finance/leases/maintenance/payments/passport/calendar/earnings/clients 大量渲染 canon 演示数据;真实用户分不清哪些是自己的。applicants 页已有正确模式(有真数据用真数据、零数据回落样本+明确标注)。
改法:把 applicants 模式推广到全部工作台页——**真实数据 > 诚实空态+单一 CTA > (可选)「查看演示」开关**。空态文案直接接漏斗(如 finance 空态 =「导入一份已签租约,收支自动记账」)。

### 3. 筛查 → 在管的桥(households 接进唯一有效的漏斗)
现状:households 全套功能上线但 0 使用——没有任何入口从筛查流程指向它。
改法:报告页/完成页在「建议批准」时出现下一步卡:「批准了?→ 导入已签租约,对话/报修/收租提醒都在站内」;applicants 详情页批准动作后同样提示。这是把一次性工具变成留存产品的关键一跳。

### 4. 修已知 bug:agent 聊天历史滞后
最新一轮气泡偶发丢失、重载后延迟出现(疑 useAgentSession 渲染 deadline 一带)。直接伤第一印象,P0 内修掉。

## P1 — 公开面专业化

### 5. 每个公开页独立 metadata
实测:搜索结果里 /tenant /landlord /partners /privacy 全显示同一句根布局默认描述。按筛查落地页模式,给全部公开页配独立 title/description(一次会话可清完)。

### 6. 首页 CTA 层级重排(不动 v8 设计语言)
现状:hero 卖平台愿景,访客不知道第一步做什么。唯一被证明的产品是筛查。
改法:主 CTA = 「免注册试一单筛查」;平台愿景保留为第二层叙事。增加**诚实数字带**:187 单筛查 · 40,844 份 LTB 判令入库 · TRREB 官方行情数据——真数字比宣言可信。

### 7. /listings 策略:7 套房源的市场比没有更糟
二选一:(a) 从主导航降级为「精选房源」板块,量起来再升回;(b) 加大 Realtor 导入扩量 + SSR 化(既有 backlog)。**建议 (a)**,成本低且立即止损。

### 8. EN 内容对齐(次优先)
筛查落地页当前 zh 为主;EN 市场值得一个对称的英文版(hreflang 分页),放 P1 末。

## P2 — 增长机制

### 9. 内容 SEO(复制落地页打法)
我们坐拥独家可写的素材:LTB 判令目录检索方法、雇主信造假的取证案例学、O. Reg. 290/98 合规筛查指南。2-4 篇指南页,每篇一个长尾词,内链到筛查落地页。中文长尾(「多伦多 房东 查租客」类)竞争极小。

### 10. 报告即获客
筛查报告是产品最好的广告——报告页脚「由 Stayloop 生成 · stayloop.ai/screening」;分享视图带注册 CTA。护照分享页(/p/)同理。

## P3 — 商业化就绪(需业务拍板)

### 11. Stripe 切 live mode
当前全站 test mode——想付钱也付不了。切 live 需要 Stripe 账号业务信息(用户操作)。
### 12. 两套 plan 存储合一
webhook 写 landlords.plan、entitlements 读 subscription 表 → 永远 free 的已知技术债,切 live 前必须修。

## 执行建议

第一刀切 **P0 全部(1-2 个会话)**:激活漏斗是当前所有问题里 ROI 最高的——获客已经免费在发生,接住它比任何新功能都值钱。P1 的 5/6/7 可以并入同一波(都是小改)。P2 内容页按周产出。P3 等拍板。
