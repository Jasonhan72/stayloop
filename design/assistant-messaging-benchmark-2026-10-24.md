# 助理消息系统再优化 · 对照两家吸收（讨论稿 · 2026-10-24）

用户 2026-10-23 给了两张图：一张多代理桌面应用（每个代理一个会话：Chief / Sales Outbound / Inbox Manager…），一张 Muse（主聊天 + 侧聊天、助理名片、右侧「今天」清单）。要求「看一下它们的消息系统设置，参考吸收好的」。本稿只做取舍，动手前由你定。

## 一、先说我们已经有的，以及不照搬的

| 我们已有 | 对应图里的 | 说明 |
|---|---|---|
| 每顶帽子多会话列表（标题 + 时间 + 助理最后一句，按时间分组，其他帽子折叠在底部） | 左栏代理列表 / Muse 的 Main chat + Side chats | 结构相当，差在「最后一句」的内容（见 ②） |
| 右侧 AI 助理面板：待办（等你点头 · 最近替你办完）/ 记忆 / 设置 | Muse 右侧名片 + 「今天」清单 | 差在呈现：我们是两段列表，Muse 是按时间的时间线（见 ④） |
| 待批卡：提议 → 批准 / 拒绝 → 60 秒撤销 → 执行回执行 | 「The top 10 look good. Send it.」 | 我们更严（每件事一张卡），图里是一句话批准一批 |
| 思考阶段提示（思考中 → 核对数据 → 整理建议） | 「✓ Salesforce → list pulled · 52 accounts」清单 | 我们只在等待时显示过程，完成后不留回执（见 ①） |
| 每日主动扫描（续约窗口、迟付、重新上架…）自动出卡 | 「Created routine · Overnight outbound」 | 我们是系统定的例行，用户不能自己定「每周一做 X」（见 ⑥） |
| 消息中心 `/messages`（人对人，按对面是谁分组，只追加 + 哈希链） | 「Messages from Account Manager and Chief」 | 图里的交接是代理之间；我们是人和人、人和助理，交接要显式折进来（见 ⑤） |

**不照搬**：① 图一的「多个代理各一个会话」——我们是一个用户一个 AI 助理（产品定义，`assistant_profiles` 一人一份），帽子不是代理；不做多代理 UI。② 「一句话批准一批」——待批卡每件事一张是 60 秒撤销和执行器核对的前提，不合并。③ 对话上方不放任何面板（现行规则），新东西都放右侧面板或卡片里。

## 二、要吸收的七项（按建议顺序）

### ① 执行回执卡 + 一句话收尾（图一的 ✓ 清单 + 「Done.」）  · S
- **现在**：助理回复是一段话；它读了什么（租约、申请、市场数据、房源搜索）、办了什么（发信、建工单）散在正文里，完成后不留痕。
- **改成**：每条助理回复可带一张小回执卡，一行一个来源或动作：「✓ 读了 2 份在管租约 · ✓ 查了 CMHC 北约克 1 卧基准 · ✓ 搜了 Rentals.ca 12 套 · ✓ 发出租金提醒 → Sarah（邮件已送达）」。正文收短，结尾一句状态（「办完了。」/「等你点头。」）。
- **怎么做**：`/api/agent/turn` 已经知道本轮注入了哪些事实组、调了哪些工具（facts / listings / market / execute 的结果都在响应里），加一个 `receipt: { read: [...], did: [...] }` 字段；`AgentChat` 在正文下渲染；提示词加「收尾一句话」。不改执行器、不改待批卡。
- **守住**：回执只列真的读过 / 做过的，来源句照旧显示；没有读到的不写。

### ② 会话列表的「最后一句」改成结果句（图一左栏）  · S
- **现在**：列表显示助理最后一条消息的开头，常是长句的前 40 字。
- **改成**：优先显示本会话最近一次回执的结果（「发出 1 封续约函 · 等你点头 1 张」/「办完了。」），没有回执才退回最后一句。随 ① 一起做。

### ③ 记忆回执 + 名片状态（Muse 的「内存暂未改——等确认后再纠正」和「Connected」）  · S
- **现在**：每轮的记忆写入（`memoryWrites`）只更新记忆面板，对话里不说；面板顶部有名字和头像，没有状态。
- **改成**：本轮写了记忆就在回执卡末尾加一行「记住了：你倾向 2 月初搬家」；没写不加；用户让它记而它没记（证据不够）要说「这条先没记，等 X 确认」。名片下加一行状态：「已连接 · 读取你的记忆、待办与租约」/ 预览模式「未登录 · 只看不记」。
- **怎么做**：`memoryWrites` 已在响应里；状态行用现有 `live` 标志。

### ④ 「今天」时间线（Muse 右栏）  · M
- **现在**：待办 tab 的「最近替你办完」是一个扁平列表。
- **改成**：按 今天 / 昨天 / 本周 分组的时间线，每条 = 标题 + 一句结果 + 时间 + ✓（失败的用 ✕ 和原因），点击跳到那条会话或那张卡；来源是现有审计里的 outcome 事件（`lib/audit/eventKinds`），加上 ⑥ 的例行任务运行记录。
- **怎么做**：改 `AssistantPanel` 的 TodoTab 渲染，数据源不变；手机端的 `/x/todo` 同一组件。

### ⑤ 「折进来的来源」行（图一的「Messages from Account Manager and Chief」）  · M
- **现在**：助理把消息中心的新消息、今日扫描的结果、其他帽子的事实都读进了提示词，但回复里看不出哪些是「别处送来的」。
- **改成**：回复顶部一行小字：「折进来的：消息中心 · 租客 Sarah 昨晚的一条消息 · 今日扫描 · 续约窗口 1 份」，每项可点，跳到那条消息 / 那张卡。消息中心里对方的新消息，助理页也能「回复」（走现有 `send_message` 卡）。
- **怎么做**：事实注入时给每组打来源标签（已有分组），响应带 `sources`；人对人消息进助理页只是展示 + 一张现有类型的卡，不新增执行器。

### ⑥ 例行任务（图一的「Run this every week → Created routine」）  · L
- **现在**：只有系统定的每日扫描；用户说「每周一帮我看一遍续约窗口」「每月 1 号提醒我收租」「每周五把这周的申请汇总给我」，助理做不了。
- **改成**：用户一句话 → 助理提议「建例行任务」卡（标题、频率、下次运行、做什么）→ 批准后生效；到点由 pg_cron 扫一遍到期的例行任务，**按现行规则出待批卡**（有执行器的动作才行；房东 / 经纪的模型不出卡，这里的卡是系统出的，和每日扫描同一条路），低风险类型（给自己的提醒、汇总）可标「免审直接做」。面板加「例行」一节：开 / 停 / 改频率 / 最近一次结果；对话里出「已创建例行任务 ⏱ 每周一 09:00 · 续约窗口检查」行。
- **怎么做**：表 `agent_routines(user_id, role, action_type, params, schedule, next_run_at, last_run_at, last_result, enabled)`；一个新执行器动作 `create_routine`；cron `agent-routines-sweep` 每小时；类型白名单按帽子：租客只有「提醒我」类，房东有 `rent_reminder` / `renewal_checkpoint` / 申请汇总，经纪有客户跟进汇总（提醒由经纪自己发，CASL）。
- **守住**：不经手资金、不碰 LTB 表格；每次运行的卡和一次性卡一样可撤销；免审类型只限「发给自己」的。

### ⑦ 主对话 + 话题 + 「送到那个话题」（Muse 的 Main chat / Side chats）  · M
- **现在**：会话是平的；主动扫描的卡落在哪个会话由代码决定；一个会话里的结论要手动复述到另一个会话。
- **改成**：每顶帽子固定一个「主对话」（置顶、不可删，扫描结果、例行任务回执、折进来的消息都落这里），其余是「话题」；助理回复下加「送到 … 话题」动作（把这段结论作为一条助理消息追加过去，现有 `appendToThread` 就能做），Muse 的「已送到 Max new school 侧聊天」就是这个。
- **怎么做**：`agent_threads` 加 `is_main`；ThreadList 置顶一行；主动扫描 / 例行任务写主对话。改动面集中在 `AgentWorkspacePage` 与 ThreadList。

## 三、建议顺序与工作量

| 批 | 内容 | 量 |
|---|---|---|
| 第一批 | ① 回执卡 + 一句话收尾、② 列表结果句、③ 记忆回执 + 名片状态 | 约 2 天，纯展示层 + 提示词，不动数据库 |
| 第二批 | ④ 今天时间线、⑤ 折进来的来源行 | 约 2–3 天，面板与注入标签 |
| 第三批 | ⑦ 主对话 + 话题、⑥ 例行任务 | 各约 1 周；⑥ 要建表、cron、执行器白名单，先做 ⑦ 给 ⑥ 的回执一个落点 |

每批一次部署 + 四个测试号核对；示例数据照规矩标「示例数据」。
