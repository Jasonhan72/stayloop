# 一个账号、三种身份：角色判定、切换与权限（研究稿，2026-09-13）

问题：一个用户能否同时是租客、房东、经纪？三种身份如何判定、如何切换、切换后功能与权限怎么区分？
本文先给结论与模型，再列现状、法规约束、权限矩阵和实施步骤。**只研究，不改代码。**

---

## 0. 结论

1. **可以同时是三种身份，法律不禁止。** 经纪自己出租房子是房东，自己租房是租客；房东也可以在别处租房。
   唯一的法定附加义务：**注册经纪以自己的利益租入或租出不动产时，须事先书面告知对方自己是 RECO 注册人，
   并尽力取得对方书面确认**（TRESA s.32，实务用 OREA Form 160/161「Registrant Disclosure of Interest」）。
   https://www.ontario.ca/laws/statute/02r30 · https://www.canlii.org/en/on/laws/regu/o-reg-567-05/latest/o-reg-567-05.html
2. **把「身份」拆成两层**：**帽子（hat）** = 账号具备的资格，服务端可查（租客 / 房东 / 经纪，经纪再分未认证 / 已认证 /
   过期）；**活动帽子（active hat）** = 当前界面上下文（导航、AI 人设、落地页）。**权限只看帽子与数据归属，
   永远不看活动帽子。** 现在的 localStorage 角色其实就是活动帽子，问题是系统把它当成了资格。
3. **判定规则**：租客帽子——任何登录用户默认拥有；房东帽子——第一次发布房源 / 做筛查 / 订阅时自动建（已有
   `claim_landlord`）；经纪帽子——只有 `agent_profiles` 行存在才有，且只有 `status = verified` 才开放经纪职能。
   后台管理员是独立体系（`admin_users`），不是帽子。
4. **切换**：Header 菜单列出账号拥有的全部帽子（目前只有租客 ↔ 房东，经纪没有入口），点击即切换，不需要重新
   登录；路由前缀（`/tenant/*`、`/landlord/*`、`/agent/*`）是活动帽子的真相，localStorage 只记「上次用的」。
5. **经纪帽子的特殊规则**：经纪以房东 / 租客帽子交易时，系统在关键动作前弹出 TRESA s.32 披露并留痕；经纪自己的
   房源在房源页显示为「房东直租 · 房东为持牌经纪（已披露）」而不是「经纪代理」；经纪不能在目录里选中自己；
   任何人不能向自己的房源提交申请。

## 2. 法规约束（与身份叠加相关的部分）

- **经纪自己交易须披露**：TRESA s.32(1)——除非注册人先向协议其他各方送达通知且对方书面确认收到，否则不得直接或
  间接购买、**租入**、交换或以其他方式取得不动产权益，也不得处置（含**租出**）不动产权益或提出要约。O. Reg. 567/05
  要求披露用清楚简明的语言并尽力取得书面确认。→ 经纪帽子存在的账号，在房东帽子出租 / 租客帽子租入时都触发。
- **为自己利益交易不需要「经纪身份」**：TRESA s.5(1)(h) 为自己名下不动产交易的人豁免注册——但注册人本来就是注册人，
  s.32 披露照样适用；RECO 行为准则（O. Reg. 365/22）对注册人的诚实、不误导、不违反《人权法》等义务在任何身份下都适用。
- **经纪替房东客户筛查租客**：属于「为他人交易」，需要书面代表协议与 Information Guide（RECO 2025-06 明确租赁同样适用）；
  筛查报告的《消费者报告法》使用者义务落在谁头上取决于谁是「使用者」——建议报告标明「代 <房东> 出具」并由房东本人
  完成 s.10(2) 事前通知与 s.10(7) 拒绝通知。
- **房东 + 租客**：无额外义务。**租客申请自己的房源**没有法律意义，只是数据错误，应阻止。
- **经纪在目录里被租客选中后**：与该租客形成代表关系是经纪与租客之间的事（Stayloop 不参与、不收费）；若该经纪同时是
  该房源的房东，s.32 披露与多重代表规则（567/05 s.22）都会触发——最简单的规则是**目录里不显示与该房源房东同一账号的经纪**。

## 3. 模型

```
auth.users (一个账号)
 ├─ tenants 行            → 租客帽子（默认有）
 ├─ landlords 行          → 房东帽子（懒建）
 ├─ agent_profiles 行     → 经纪帽子：pending | verified | rejected | renewal_due | expired
 └─ admin_users 行        → 后台管理员（不是帽子）

活动帽子 = 路由前缀推导（/tenant /landlord /agent），回退到 localStorage 上次记录
```

**判定与门**

| 帽子 | 存在条件 | 开放的功能 | 服务端门 |
|---|---|---|---|
| 租客 | 登录即有（匿名亦可） | 找房、看房意向、申请、护照、租约签署、维修、Luna | RLS 按 uid |
| 房东 | `landlords` 行 | 发布房源（进审核）、筛查、租约、维修、财务、Logic、订阅 / 解锁 | RLS 按 uid；付费门 `hasProAccess` |
| 经纪（未认证） | `agent_profiles.status ≠ verified` | 认证页；工作台只读（Brief 可聊，任务 / 客户 / 日历空态 + 认证入口）；**不进目录、不可被联系** | `agent_profiles.status` |
| 经纪（已认证） | `status = verified` 且未过期 | 目录展示与被联系、客户、任务、日历、代客发布房源（须自述代表协议）、（冻结）转介 | 同上 + 到期检查 |

**切换**

- Header 头像菜单：列出账号已有的帽子，每项写清做什么（找房 · 申请 · 签约 / 管房 · 筛查 · 收租 / 客户 · 带看 · 目录）；
  没有的帽子显示「成为房东」「成为经纪（需 RECO 认证）」入口。点击 = 跳到该帽子主页；不写 localStorage 也可以，因为路由
  前缀决定活动帽子；localStorage 只用于「打开首页时回到上次的帽子」。
- 不需要二次确认或 PIN：三个帽子都是同一个人，数据本来就按 uid 隔离。
- 手机端：底栏随路由前缀变化（现有行为）；头像菜单同桌面。
- AI 助手：切换帽子 = 切换到该帽子的会话与记忆（现有 `bootstrap_agent_session(p_role)`），互不串用；反思画像按帽子分开
  （现有）。

**跨帽子规则（新增守卫）**

1. 不能向 `listings.landlord_id` 属于自己的房源提交看房意向或申请（前端隐藏按钮 + 后端 / RLS 校验）。
2. 目录（AgentPicker）排除与当前房源房东同一账号的经纪；排除正在浏览的用户自己。
3. 经纪帽子存在时：房东帽子「发布房源」与「接受申请 / 发送租约」、租客帽子「提交申请」前，弹 TRESA s.32 披露
   （预填注册名、注册号、经纪公司），生成可下载的通知并记录对方确认；房源页把该房源标为「房东为持牌经纪（已披露）」。
4. 经纪帽子代客户做的筛查带 `on_behalf_of`（客户房东名 / 代表协议日期），报告与通知信写明；没有代表记录的经纪不能发起筛查。
5. 租客护照、申请记录只对租客帽子可见；房东帽子看不到自己账号的租客资料，除非租客帽子主动分享（现有分享机制）。
6. `households` 的 `property_manager` 角色是「在管租约」里的席位，不是账号帽子；一个账号可以在某个 household 里是
   property_manager 而在另一处是 tenant，互不影响。

## 4. 权限矩阵（含跨帽子列）

| 能力 | 租客 | 房东 | 经纪·未认证 | 经纪·已认证 | 跨帽子规则 |
|---|---|---|---|---|---|
| AI 助手 | Luna | Logic | Brief（可聊） | Brief | 每帽子独立记忆 |
| 浏览 / 收藏房源 | ✓ | ✓ | ✓ | ✓ | — |
| 看房意向 / 申请 | ✓ | — | ✓（以租客帽子） | ✓（以租客帽子） | 不能对自己的房源；经纪须 s.32 披露 |
| 护照、授权分享核验 | ✓ | — | — | — | 只对租客帽子可见 |
| 发布房源 | — | ✓ | — | ✓ 代客（须代表协议自述） | 经纪自己的房源走房东帽子 + s.32 披露 |
| 租客筛查 | — | ✓ | — | ✓ 代客（`on_behalf_of`） | 报告写明代谁出具 |
| 租约填写 / 签署 | 签 | 填 + 签 | — | 填（代表方） | 经纪自租 / 自出租须 s.32 |
| 目录展示、被租客联系 | — | — | ✗ | ✓ | 排除房源房东本人 |
| 客户 / 任务 / 日历 | — | — | 空态 + 认证入口 | ✓ | — |
| 转介 / 佣金 | — | — | — | 冻结 | 律师意见后再定 |
| 订阅 / 解锁付费 | — | ✓ | ✓（经纪档） | ✓ | 房东付，永不向租客收 |
| 删除自己的数据 | ✓ | ✓ | ✓ | ✓ | — |

## 5. 实施步骤（待你决定后再做）

1. **`my_hats()` RPC**（SECURITY DEFINER，只返回当前用户）：`{ tenant: true, landlord: bool, agent: status|null, admin: bool }`；
   `useAuth` 增加 `hats`，`role` 改为「路由前缀 → localStorage 回退」的活动帽子。
2. **Header 三帽切换**：按 `hats` 渲染；没有的帽子给入口；经纪未认证显示「待认证」小标。
3. **守卫**：向自己房源申请（前后端）；目录排除本人与房源房东；经纪代客筛查需 `on_behalf_of`（先做字段与文案，代表协议
   记录后续）。
4. **TRESA s.32 披露组件**：经纪帽子存在时，在房东出租 / 租客申请路径上弹出；生成 PDF 或可打印页并记录确认（新表
   `registrant_disclosures`）。
5. **房源页标注**：房东为持牌经纪时显示「房东直租 · 房东为持牌经纪（已披露）」。
6. **文案**：定价页三角色口径对齐帽子模型（经纪档说明「需 RECO 认证」）。
