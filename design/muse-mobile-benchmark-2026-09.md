# Muse（Meta 个人 AI 助手）手机端 UI/UX 对照 → Stayloop 手机端可借鉴的方法（2026-09-22）

研究对象：Muse from Meta（muse.ai，2026-09-08 发布，iPhone 应用 v8.0，Mac 应用 09-17；免费 + 每周额度，付费解锁）。
来源：App Store 页面的六张应用截图（唯一能看到真实界面的公开材料）、Meta 设计负责人的产品设计文《How We Designed Muse》
（introducing.muse.ai）、安全文（research.meta.ai）、ai.meta.com/muse 与 muse.ai 营销页。**Web 版 muse.ai 需要登录，
我没有用你的账号登录**；结论全部来自公开截图与文字。

Muse 是「通用生活助手」（购物、订餐、家庭日历、健身、理财），Stayloop 是「租房三角色助手」。可借鉴的是**手机端把一个
会自己干活的助手怎么摆出来**，不是它做的事。

## 1. Muse 手机端长什么样（六张截图 + 设计文）

| 屏 | 结构 | 设计文里的理由 |
|---|---|---|
| **主屏 = 一条长对话** | 顶部居中一个头像 + 名字（用户自己起，如 Veda），头像下一行小字「正在做什么」；下面是气泡流；底部输入条只有「+ · Message · 🎙」 | 「不是逐轮问答」：可以连发多条、可以打断；气泡是为了在消息乱序到达时还读得清 |
| **头像可点** | 点头像 → 完整活动日志 + 已批准的权限 | 「看不见的就不会信任」，后台在跑的东西要能随时看 |
| **审批卡在对话里** | 「Checkout · Muse wants to place an order on ncoss.com」：商品图、价格、卡末四位、预计总额、**Deny / Allow** 两个按钮；「Review order」可展开 | 「对话不够用的地方必须是确定性 UI」：结构化审批卡 + 明确接受/拒绝；默认放行普通浏览、**只在难以撤销的动作上停下**，避免「横幅盲」 |
| **浏览器卡** | 「Browser · Selecting seats…」缩略图 + 「Open browser」按钮 | 助手在网页上操作时用户随时能接管 |
| **产物卡（Artifacts）** | 填好的 PDF 表单卡（「Field trip permission slip · PDF」）、理财看板深色卡（三个数字 + 「Finance tracker」链接） | 「一段文字不是所有答案的形状」——行程要表格、开支要看板 |
| **想法（Ideas）页** | 一列「I can follow up on your airline refund / I can find a bigger stroller for Luca…」，每条一句理由，点了就交给它 | 早期测试发现「能做的太多，用户不知道从哪开始」，于是让助手主动列出它能替你做的事 |
| **目标（Goals）页** | 分段：Tracking（正在跟的）/ Goals（长期目标，每条带子任务与进度）/ Create a goal（分类）；「Show N more」折叠 | 长期任务要有一个不同于活动日志的「计划视图」 |
| **底栏** | **5 个图标、无文字**：对话 · 任务 · 想法(灯泡) · 目标(勾) · 连接的应用(九宫格) | — |
| **主动消息** | 后台跑完先判断「值不值得打扰」，只在真正新的或需要你决定时推；用户可让它「少一点 / 多一点 / 关掉」 | 主动消息的门槛必须高 |
| **记忆** | 「Memory files」可直接读、改、让它「忘掉某件事」；权限按应用分读/写、按次/按任务/按时段/永久 | 透明与可控 |

视觉：白底、单一靛蓝强调色（≈ #4F63F6）、大圆角浅灰卡、头像居中、留白多；截图上没有任何数字堆砌、没有 KPI 条。

## 2. Stayloop 手机端现状（375px 实测，2026-09-22）

| 项 | 现状 | 与 Muse 的差距 |
|---|---|---|
| 主屏 | `/tenant/agent`：预览横幅 → 对话卡（高 70vh，含助手头像 + 「在线 · 读取你的记忆」）→ **往下滚才有** 待办审批 / 状态瓦片 / 流程 / 建议 / 记忆 / 相关页 | 审批卡在手机上落在对话下方、首屏看不见；Muse 把审批放在对话流里 |
| 头像 | 对话卡头部一行状态是固定文案「在线 · 读取你的记忆」，不可点 | Muse 的头像下是**真的在做的事**，点开是活动日志与权限（我们有 `/tenant/audit`，没有入口） |
| 底栏 | 租客 8 项（主页 申请 Passport 租约 维修 付款 审计 设置），9.5px 文字标签，2026-09-13 刚从溢出修回来 | Muse 5 项无文字。我们 8 项是把桌面侧栏原样压扁 |
| 主动性 | `proactive` 路由每日生成待办（续约 90/60/30、租金提醒），但**没有任何推送**；用户要自己打开工作台才看到 | Muse 有推送并有「少 / 多 / 关」的旋钮 |
| 想法 | 对话空态有 5 张快捷卡（`SUGGESTIONS`）、右栏有 `RecommendationDeck` | 都是静态；Muse 的 Ideas 是按用户目标与记忆生成、带理由 |
| 目标 | `WorkflowStatusPanel`（找房 → 申请 → 签约… 阶段）、`StatusOverview` 瓦片 | 形态接近 Goals，但在手机上排在对话之后 |
| 产物 | 房源卡、行情卡（含 TRREB 图）、商业对比表、草稿房源卡、待办卡——都已经在对话里 | **这一项我们不差**，甚至更多 |
| 审批卡 | `ApprovalActionCard`：标题、摘要、收件人、**会用什么数据 / 不会用什么数据**、风险等级、批准/拒绝 | 信息量比 Muse 多（data_scope / excluded_data 是我们独有的），只是位置不对 |
| 记忆 | `PrivateMemorySnapshot` 只读列表；对话里可以说「忘掉」 | Muse 可直接编辑 |
| 应用形态 | 纯网页，无 manifest、无 service worker、无「添加到主屏」 | Muse 是原生应用；我们至少可以做 PWA |

## 3. 建议采用（按优先级）

### P0 · 手机端信息架构（一次改到位，桌面不动）

**A. 底栏 8 → 5，学 Muse 的「助手 · 待办 · 想法 · 进度 · 更多」。**
- 助手（对话）· 待办（待批审批 + 申请/租约里等你动作的事，带红点计数）· 想法（助手能替你做的事）· 进度（Workflow 阶段 + 状态瓦片，
  即 Muse 的 Goals）· 更多（原 8 项里其余页面：Passport / 维修 / 付款 / 审计 / 设置，一个抽屉列表）。
- 三角色各自映射：房东 = 助手 · 待办 · 想法 · 进度（申请人 / 租约 / 续约）· 更多；经纪同理。
- 图标 + 4 字以内标签（Muse 无标签，但我们的图标没有它那么通用，保留标签、字号回到 11px——5 项装得下）。
- 桌面侧栏保持 8 项不变；这是 `WorkspaceShell.Rail` 的 `md:` 以下分支。

**B. 审批卡进对话流。** 手机上 `PendingActionsPanel` 不再排在对话下方，而是作为对话里置顶的一组卡（Muse 的 Checkout 卡就在气泡之间）；
批准 / 拒绝后卡片折叠成一行「已批准 · 已发送给 …」。桌面右栏不变。**保留我们的 data_scope / excluded_data 两行**——这是比 Muse 更好的地方。

**C. 头像下一行「正在做什么」+ 点头像看活动日志。** 对话卡头部的固定文案换成真实状态：有运行中的 workflow 阶段就显示
「正在：核对 3 份申请 · 续约窗口扫描」，空闲显示「空闲 · 上次：今天 08:00 续约扫描」。点头像 → 底部弹出「活动日志」（读 `agent_audit_events`
最近 20 条，链到 `/x/audit`）+「已授权的数据」（记忆分类计数 + 设置入口）。

**D. 「想法」页 = 主动建议，带理由。** 内容来源：① `RecommendationDeck` 现有项；② 由反思画像 `user_model`（`current_focus / goals`）生成的
2–4 条「我可以替你…」（每条一句为什么：「因为你说过 11 月要搬」）；③ 系统事实（续约窗口、未完成的申请材料、过期证件）。点一条 = 把那句话
送进对话。**不新增模型调用**：①③ 是确定性的，② 复用反思画像里已经存在的字段，模板拼句。

**E. 「进度」页 = Goals。** 把 `WorkflowStatusPanel` + `StatusOverview` 合成一页：上半「正在跟的」（阶段条），下半「你的事」（瓦片），
「Show N more」折叠。手机上首屏不再需要把这些塞在对话后面。

### P1 · 主动性与可安装

**F. 推送。** 先做 **PWA**（`manifest.json`、图标、`display: standalone`、iOS `apple-mobile-web-app-*` meta、「添加到主屏」引导条一次性显示），
再做 **Web Push**（service worker + VAPID，Supabase 表 `push_subscriptions`）：`proactive` 路由生成待办时若用户订阅了推送就发一条
（「续约窗口：Mia · 3 月 31 日到期，方案已备好」）。门槛学 Muse：**只推需要你决定的**（待办卡）与**真正新的**（申请到达、看房请求），
不推「已完成」类；设置里三档「少 / 默认 / 关」。iOS 16.4+ 支持 PWA 推送，前提是用户已添加到主屏。

**G. 记忆可编辑。** `PrivateMemorySnapshot` 每条加「编辑 / 忘掉」（`user_memories` 本来就是 RLS 本人可写；忘掉 = 删行 + 审计事件）。
反思画像 `user_model` 也展示为可读文本并允许「这条不对」。

### P2 · 视觉

**H. 对话头部去掉「在线 · 读取你的记忆」这类装饰文案**，换成 C 的真实状态；头像稍大（40px），名字下的状态 12px 灰。
**I. 手机端对话卡去外框**：Muse 的对话是通栏的，气泡直接落在页面底色上；我们 375px 上还有一层圆角卡 + 边框，白白吃掉 2×16px。
`AgentChat` 在 `sm:` 以下取消 border / radius / shadow，输入条贴底栏之上（`sticky bottom-16`）。
**J. 输入条简化**：「+ · 写点什么 · 🎙 · ↑」已经和 Muse 一样，不动。

## 4. 不抄

- **Secure VM / 共享浏览器 / 替你填表下单**：我们的助手不代操作第三方网站；租房里「难以撤销的动作」只有发信、发房源、签约，已经全部走审批。
- **购物、一次性卡号、Link 购买保护**：无关。
- **头像自定义画像 / 人格商店**：起名我们有（onboarding），画像不做——三角色助手的身份是角色色 orb，不是宠物。
- **去掉标签的纯图标底栏**：我们的图标（护照、筛查、审计）不如「对话 / 灯泡 / 勾」直观，保留短标签。
- **18+ 年龄门**、**每周额度墙**：与我们的免费策略不一致。

| 4 | G 记忆可编辑 | `PrivateMemorySnapshot` | 否 |
