STAYLOOP · PROPOSAL · 2026-09-23

第三方服务市场：怎么接进 Stayloop，服务流程怎么走

对用户稿《第三方服务市场：以 GTA 精选维修网络切入，以嵌入式保险扩大单户收入》（investor one-pager）的落地方案。先给结论与流程，再决定做不做。

依据：用户稿 · 现有代码与生产库（2026-09-23 实数）· 安省法规一手来源（文末）· 三家可比公司公开材料。本文不含任何已实施的改动。

0. 结论先行

建议做，但把顺序反过来：先做「派单与履约记录」，再做「收款与抽成」，保险只做「入口」不做「转介计酬」。
原因有三：① 我们的护城河是「工单从租赁流程里长出来」，这一段（AI 分诊 → 待批卡 → 执行器 → 在管租约共享中心 → 审计）已经全部存在，把它延长到服务商那一端是加法，不是新系统；② 一旦平台经手资金，就同时承担《消费者保护法》的估价规则、HST、退款与争议——这要等有真实工单量再背；③ 安省对无牌方的保险推介计酬有硬限制，现有的「租客保险转介卡」已经是合规形态（只放链接、不按成交收费），律师意见拿到前不要往前走。
先看清需求密度。生产库此刻：报修工单 1 张、在管租约 1 份（都是 [TEST] 数据）、房东 7 位、经纪公司 0 家。市场的第一阶段必须与「在管租约」的增长绑在一起——没有在管租约就没有工单，没有工单就没有派单。所以本方案的 Phase 0 是把已有的报修闭环补齐、让每一份在管租约都能产生工单，而不是先去招 30 家服务商。

2. 对用户稿的逐项评价

用户稿要点判断说明与修正
先精选网络（curated），再开放入驻 + 评分 + Vendor SaaS同意顺序对。补一条：精选网络之前还有一步「房东自己的联系人」——很多小房东已有固定师傅，先让他们把工单派给自己的人（只要一个邮箱），我们就有了履约数据与评分样本，再去招募陌生服务商。
三层收入：维修抽成 → 保险 referral → Vendor SaaS同意，改顺序按「风险从低到高」排，实际是 Vendor SaaS（订阅，不经手交易）风险最低，维修抽成（经手资金）次之，保险 referral（受牌照法约束）最高。首期收入只做 Pro 订阅里的「派单功能」（不另收），抽成留到 Phase 2。
保险：持牌方承保与销售，Stayloop 嵌入入口；referral 结构待律师同意，加硬约束安省《保险法》与 FSRA 对无牌方的推介计酬有限制（不得因保单成交而分佣，FSRA 的许可适格指引把「对无牌销售控制不足」列为重点）。现有转介卡（固定链接、无计酬）就是可以立刻扩到签约 / 续约节点的形态；任何按成交计费的结构在律师书面意见前不上线。
自动派单：房东预设预算、品类与紧急规则同意，加两条法规闸① RTA s.27：非紧急进入须提前 24 小时书面通知（8:00–20:00）；s.26：紧急情况可不通知。所以派单卡必须携带「进入方式」并在非紧急件上自动生成通知文本、由房东批准后发给租客；② 自动派单只在房东预设策略内触发，且仍生成待批卡（紧急件允许「自动批准 + 15 分钟撤销」而不是跳过卡片）——保持「AI 提议、人决定」的产品原则。
供给端资格：公司注册、持证工种、商业责任险、WSIB同意，具体化见第 5 节资质矩阵：Skilled Trades Ontario 有 23 个强制工种（含水管工 306A、电工 309A、制冷与空调技工 313A），公共注册库可查；电气承包须 ESA 持牌承包商；燃气设备须 TSSA 认证技师；WSIB 清关号——出租物业的维修不是「屋主自住的家装」，豁免不适用，须查清关。
责任链：标准范围、变更授权、前后照片、验收、争议同意，落到法规《消费者保护法》估价规则：最终价不得超出估价 10%，除非消费者同意新范围——这条要做进产品（报价 → 增项须房东再批准 → 发票对照报价）。新《消费者保护法（2023）》已通过但配套条例未生效，现行仍是 2002 版。
目标：租赁内的闭环履约，而非「找师傅」同意Jiffy（多伦多，2024-11 被 Intact 收购）与 HomeStars（Angi）都是消费者发单的通用平台；Lessen 是美国机构级端到端。我们的错位是「工单从租约里长出来、验收由租客确认、记录留在物业时间线」——这三点他们都没有。
试点 6 个指标同意全部能从 work_orders 的事件表算出来，见第 7 节。
未写但必须补的—RTA s.134：不得向租客收取任何费用——工单的付款方永远是房东（或房东的物业公司），产品里不能出现「租客付」的入口；PIPEDA：服务商只看到完成工单所需的信息（地址、联系方式、照片、进入许可），看不到租约、筛查、租金记录；平台身份：合同上 Stayloop 是撮合与记录方，不是承包商，服务合同在房东与服务商之间——这一点要写进服务商入驻协议与房东端条款，律师确认。

租客 / 房东① 发起对话、照片或在 /h 报修表；AI 补齐四件事（哪里 / 类别 / 进入许可 / 宠物）；紧急件先给「现在该做什么」

3.1 紧急件专线（无暖气、停水、燃气、淹水、门锁、CO）

  • 租客助手先给「现在该做什么」（燃气 → 离开并打燃气公司；漏水 → 关总阀；没暖气 → 电话房东留证据），再出工单；工单 priority 强制 high，标 emergency=true。
  • 房东若预设了「紧急自动派单策略」（品类 + 上限金额 + 候选名单），③ 与 ⑤ 合并成一张自动批准、15 分钟可撤销的卡，推送 + 邮件同时发；未预设则照常人工批准，但推送级别为 approval（两档都推）。
  • RTA s.26 允许紧急进入不提前通知——卡片与租客通知写明依据；非紧急件一律走 24 小时书面通知。

三条产品硬规则：① 需持证工种的工单，候选列表只出现资质在有效期内的服务商，其余灰掉并写明原因；② 每次派单在 work_order_events 里记录「派单时对照的资质编号与到期日」（用户稿的「派单前后保存核验记录」）；③ 资质到期 → 自动停派单 → 服务商与管理员各收一封提醒（到期前 30 天）。

5.1 与用户稿一致的合规红线

  • 平台不替代持牌主体：Stayloop 撮合、记录、通知；服务合同在房东与服务商之间；争议裁定不是法律裁决，双方仍可走 LTB / 小额法庭。
  • 保险：承保、建议、报价解释与销售由持牌保险公司 / 代理 / 经纪完成；Stayloop 只放入口，不按成交计酬；具体结构由安省保险律师与合作方确认后再动。
  • 租客不付费（RTA s.134）；估价 10% 规则（CPA）；进入通知（RTA s.26 / s.27）；维修义务在房东（RTA s.20）——四条全部进 lib/ontario/rules.ts 并在卡片与邮件里引用编号。

9. 需要你决定的五件事

  1. 做不做 Phase 0（2 周，不涉及服务商与资金，纯粹把报修闭环补齐并让房东能派给自己的人）。我的建议：做，它本身就是「租中」模块该有的功能。
  2. Phase 1 的启动条件：我建议「连续一个月 ≥30 张真实工单」再招募服务商；或者你决定用你自己的房源与熟悉的服务商先跑 5–10 单做样板。
  3. 首批品类：建议水管 / 电气 / 供暖空调（紧急件最多、持证要求最清楚）；用户稿写 3–5 个，第四、五个建议电器与门锁。
  4. 资金是否经手：Phase 1 线下付款只记录，Phase 2 再上 Connect。如果你想第一天就抽成，需要先把 CPA / HST / 争议退款的责任一起背上。
  5. 保险：现在只把现有转介卡扩到签约与续约节点（零风险）；计酬结构等律师意见。是否现在就去找安省保险律师与一家持牌合作方谈？
