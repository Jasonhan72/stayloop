# EliseAI 对照研究 → Stayloop 可采用的方法（2026-09-22）

研究对象：eliseai.com（2026-09-22 用内置浏览器逐页阅读：首页、Property Management、Prospect Management、
AI-Guided Tours、Renewals、Lease Audits、Fee Transparency、Maintenance、Delinquency、MeetElise（VoiceAI 试用）、
Engineering、Customer Stories、Integrations、Single-family / Owners）。计算样式取自页面实际渲染值。

EliseAI 面向的是**美国机构级多户运营商**（数万套、有 PMS/CRM、有租赁办公室与呼叫中心），Stayloop 面向的是
**安省小房东、租客与持牌经纪**。所以本文分三类：**照搬**（方法与我们产品逻辑一致）、**改造后采用**（同一动机，
换成我们做得到、合规的形式）、**不抄**（与我们的事实、规模或法规相悖）。

---

## 1. EliseAI 在做什么（事实摘要）

### 1.1 产品结构：一条对话贯穿租客全生命周期
| 阶段 | 产品 | 核心承诺 |
|---|---|---|
| 找房 | Prospect Management | 24/7 回复所有渠道的咨询、按运营方设定的「模式」（可切换的资格条件）预筛、直接约看房；同一个潜在租客的邮件 / 短信 / 电话 / 网聊**并入一条对话** |
| 看房 | AI-Guided Tours | 非工作时段自助看房（智能锁 + 身份核验），看完自动跟进 |
| 签约 | Lease Audits | 账本 vs 租约逐项对账，找出漏收 / 多收 |
| 入住后 | Fee Transparency | 全部费用集中配置一次、按辖区自动生成披露页与 PDF，各渠道口径一致 |
| 居住 | Maintenance / Delinquency | 报修分诊、紧急事项转人；催收给出付款计划、把担保人拉进对话 |
| 续约 | Renewals | 到期前 30/60/90 天三次触点、意向看板、带上下文升级给人 |
| 横向 | VoiceAI / EliseCRM / Integrations | 7 种语音 51 种文字语言；CRM；与主流 PMS / 看房 / 租约系统集成（可筛选的集成目录） |

**关键抽象**：不是「一堆功能」，而是「租客一条时间线，AI 在每个节点先动、人只处理升级」。

### 1.2 页面模板（每个产品页约 9 段，结构完全一致）
1. Hero：H1 + 一句副标 + 产品界面截图 + **工作邮箱表单**（就地留资）；hero 下方一排信任 chip（评分、SOC 2 Type II）
2. 眉标 / H2 / 一段话（问题陈述）
3. 2–3 张「收益卡」，每张配真实 UI 截图
4. 客户引言（姓名 / 职位 / 公司）
5. VoiceAI 横带（跨产品复用）
6. 3 张能力卡
7. 案例 + **一个大数字**（每页只有一个：「lead-to-lease 时间 −65%」「37% 的看房在非工作时段」「续约留存 +9%」）
8. FAQ 手风琴（8–13 问，页页都有，且是该产品专属的问题）
9. 结尾一句话 CTA

### 1.3 视觉系统（计算值）
| 令牌 | 值 |
|---|---|
| H1 | Inter Tight 72px / weight 450 / lh 75.6 / ls −0.72 |
| H2 | Inter Tight 60px / 450 |
| 正文 | Inter 20px / lh 30 / #515152 |
| 眉标 | 全大写 16px / 500 / 紫 #7638FA |
| 墨色 | #0E0D0C |
| 底 | 白 + hero 淡紫渐变；手机端 hero 换深色渐变、CTA 上下堆叠 |
| 内容宽 | 1160 / 1440（通栏）/ 616（文字列）/ 800 / 960 |

要点：**标题字重轻（450）、字号大、字距收紧**；正文 20px 比一般 SaaS 大一号；全站单一强调色；每屏只做一件事。

### 1.4 信任与转化模式
- 每页一个可核的大数字 + 出处（客户名）；不堆数字
- 每页专属 FAQ（同时是 SEO 结构化数据）
- 「试一试」入口：MeetElise 页给出示例问题，让访客直接和 AI 对话
- 信任 chip：第三方评分、SOC 2、隐私政策链接
- 客户故事按产品筛选；集成目录按类别筛选
- 表单只要工作邮箱一个字段

## 2. Stayloop 现状对照

| 维度 | EliseAI | Stayloop（2026-09-22 线上） |
|---|---|---|
| 生命周期覆盖 | 找房 → 看房 → 签约 → 费用 → 报修 → 催收 → 续约，一条线 | 找房（租客管家 + Realtor.ca）、筛查（核心，深度最强）、租约 e-sign、在管租约（导入 / 对话 / 租金自述 / 报修）、续约扫描（proactive）、报修票据。**看房预约、费用披露、催收流程无** |
| 统一对话 | 每个潜在租客一条对话，跨渠道 | 三个角色各自一个管家；房源页「联系」是邮件 / 电话，**申请与看房意向没有汇入管家对话** |
| 主动触点 | 30/60/90 天续约、催收计划 | `proactive` 路由已有续约窗口扫描 + 月末租金提醒，但**没有 30/60/90 三阶节奏**，也没有意向看板 |
| 费用透明 | 集中配置 + 辖区披露 | 房源页有押金 / 物业费两格；**没有「入住前你要付什么」一览**（安省本来就简单：一个月押金 + 钥匙押金 + 押金利息，RTA s.105–106） |
| 页面模板 | 9 段固定模板，页页 FAQ | 首页 = 助手对话（已定稿）；三角色页 = RoleLanding（hero / journey / scenario / stats / valueBand），**无 FAQ**；筛查页有 FAQ + 对照表；定价页有 FAQ |
| 证明数字 | 每页一个 | 首页深色带四个真实计数（`/api/public/stats`），角色页 `stats` 三格是**设计样例文案** |
| 试一试 | MeetElise 示例问题 | 首页 Hero 本身就是可用对话（比他们更进一步），但**角色页与筛查页没有把访客送回对话**的入口 |
| 信任 chip | 评分 / SOC 2 | 无第三方评分（也没有，不能编）；有隐私页、数据驻加、OHRC 合规声明分散各处，**没有集中成 chip 行** |
| 字体系统 | 72/450 大轻标题、20px 正文 | h1 52px / 800、正文 14–15px，信息密度高、偏「工具」感 |
| 留资 | 工作邮箱一栏 | 登录 = 魔法链接，等价于一栏邮箱，但角色页 CTA 指向 onboarding 而非就地输入 |

## 3. 建议采用（按优先级）

### P0 · 照搬（不改产品事实，只改呈现；可直接落地）

**A. 页页 FAQ。** 三角色页各加 6–8 问，问题必须是该角色真会问的、答案是我们能兑现的事实：
- 房东：免费能筛几次 / 筛查看什么、不看什么（OHRC）/ 申请人怎么授权 / 报告能否给申请人 / 数据存在哪 / 我要不要自己注册消费者报告机构 / 我能让租客付筛查费吗（不能，RTA s.134）
- 租客：管家找的房源来自哪里 / 我的资料谁能看 / 筛查报告我能索取吗（《消费者报告法》s.10(7)）/ 为什么找不到「在线交租」 / 商业场地也能找吗
- 经纪：认证要什么（RECO 号，不传证件）/ Stayloop 收不收费（不收）/ 转介佣金（冻结中，如实说）/ 筛查费能不能转嫁申请人（不能）/ TRESA s.32 披露怎么做
FAQ 同时输出 FAQPage JSON-LD（筛查页已有同一模式）。

**B. 每页一个可核实的数字。** 角色页 `stats` 三格换成 `/api/public/stats` 的真实计数各取一个（房东：已完成筛查数；租客：可见房源数 + TRREB 季度数；经纪：LTB 目录判令数），并写明数据来源与更新时间。设计样例数字全部退出营销页。

**C. 「试一试」回流。** 角色页与筛查页每个能力卡加一条例句（「帮我看这份申请要注意什么」），点击带 `?ask=` 跳回首页 Hero 对话（`HomeNext` 已支持把痛点例句送进对话，只需接受 URL 参数）。这是我们比 EliseAI 强的地方，要让每一页都用上。

**D. 信任 chip 行（只写事实）。** hero 下一行：「数据库驻加拿大 · 不收 SIN · OHRC 租房政策口径 · 不是消费者报告机构 · 测试期免费至 2026-10-14」。每个 chip 链到隐私页 / 筛查页对应段落。禁止出现评分、客户数、正常运行率。

### P1 · 改造后采用（有产品逻辑要补，一两周内可做）

**E. 房源页「入住前费用一览」。** 按 RTA 只有三项合法：租金押金（≤ 一个月，只抵最后一月，s.106）、钥匙押金（≤ 更换成本，O. Reg. 516/06 s.17）、押金年息（按指导比例，s.106(6)）。房源页在「建筑信息」旁加一张固定卡：「第一笔款 = 首月租金 + 押金 $X · 不允许的费用：申请费、信用检查费、宠物押金、清洁押金」。数据已在 `listings.deposit / rent`，无需新列；这是 EliseAI Fee Transparency 的安省版，而且比他们更简单，因为法律把清单定死了。

**F. 续约 30/60/90 三阶。** `proactive` 路由已扫续约窗口，改为三阶：90 天生成「行情对照 + 建议 A/B」待办、60 天生成续约信草稿（现有 `send_renewal_letter` 执行器）、30 天未回复升级为「需要你打电话」提醒。房东工作台加「续约意向」瓦片（已回复 / 未回复 / 不续）。

**G. 看房意向进对话。** 房源页「预约看房」目前是演示弹窗（无 DB 写入）。最小实现：意向写 `showing_intents`（表已有），房东管家收到「X 想看 Y，建议三个时段」待办，房东批准后发邮件（现有 `send_message` 执行器）。这补上 EliseAI「一条对话」中我们缺的一环，不做智能锁。

**H. 「联系」统一入口。** 房源页的邮件 / 电话保留，但加「让 Luna 替我问房东」按钮，把问题送进租客管家，由管家汇总后生成给房东的一封邮件（待确认卡）。同一租客对同一房源只有一条线程。

### P2 · 视觉与文字（需先出蓝本、用户定稿后改）

**I. 标题系统向「大而轻」靠。** 营销页 h1 52/800 → 56–64/600、字距 −0.03em；h2 36/500；正文 15 → 17px、行高 1.6；眉标保持 mono 大写但 13px。工作台不动（工具型界面密度是对的）。配色不动（v9 Flinks 蓝系已定稿）。

**J. 角色页模板补两段。** 现有 RoleLanding：hero → journey → scenario → stats → valueBand → CTA。加「FAQ」（A）与「试一试」（C），把 `stats` 换真数（B），hero 下加 chip 行（D）。段落顺序改为：hero+chips → 三张收益卡（各配一张真实界面截图或例句）→ journey → scenario → 一个数字 → FAQ → CTA。这是 EliseAI 模板的 6 段精简版。

**K. 手机端 hero。** 学他们：手机上 hero 换成墨蓝 #1B1B3C 深底、白字、CTA 上下堆叠（桌面端不变）。首页 Hero 是对话框，不适用；只用于三角色页与筛查页。

**L. 集成 / 合作页如实化。** `/partners` 已去掉不存在的合作；可以改成 EliseAI 式「数据来源目录」（Realtor.ca 抓取、TRREB 季报、LTB 开放数据、联邦公司注册库、安省法院门户、Bank Act 附表、Veriff / Flinks / Equifax 待生产凭证），每项标状态（已接入 / 测试 / 待凭证）。这比「合作伙伴 logo 墙」诚实，也回答了「你们的数据从哪来」。

## 4. 不抄

- **700 家客户 logo 墙、G2 评分、SOC 2 徽章**：我们没有，编一个就是虚假宣传。
- **「lead-to-lease −65%」类百分比**：来自他们客户的内部数据，我们没有可审计的对照组；只用绝对计数。
- **Cookie / 广告横幅、Apollo 表单弹窗**：与我们的隐私姿态相反。
- **催收（Delinquency）产品**：安省 RTA 下小房东的欠租路径是 N4 → L1，AI「付款计划谈判」在小房东场景既无量又有法律风险；管家已能起草 N4 说明，不再扩。
- **自助看房 + 智能锁**：硬件与保险问题，非本阶段。
- **Lease Audits**：那是账本 vs 租约的机构对账；我们的在管租约是自述数据，没有账本可审。
- **VoiceAI 电话**：成本与合规（录音同意）不匹配现阶段。
