# V1.0 正式版 · 范围与路线图（讨论稿，2026-10-13）

**这是讨论稿，不是执行令。** 四条调研线的原稿在 `design/research/v1/`（租客 `tenant-tools`、经纪 `agent-tools`、房东 `landlord-retention`、开放 API `open-api`，各自带对标原料与法规原文），法规核查回执 `legal-check-2026-10.md`。本稿只做取舍与排序；任何一项动手前都要你再确认。

## 1. 一句话结论

**前提（用户 2026-10-13 说明）：正式版尚未发布，现有筛查全部是测试，所以下面的漏斗数字不是「用户流失」，而是「上线前的产品形态只有筛查一个入口、后面没有路」的证据。** V1.0 不是加功能，是把三件事做实：① 在正式发布前把筛查之后的路铺好（现在的测试数据里，筛查之后的每一步都是 0）；② 给租客和经纪一个不靠房源数据也成立的工具（申请包、事实包、收件链接）；③ 把规则与基准做成对其他 AI 开放的正门（REST + 远程 MCP）。** 在线收租、LTB 代填、MLS 数据、按姓名查记录（注册前）都不做。

## 3. V1.0 范围建议

工作量：S ≈ 1–2 天、M ≈ 1 周、L ≈ 2 周以上。「门槛」是动手前必须满足的前置条件。

### 3.2 可选（V1.0 之后，按需）
- 经纪替房东客户填标准租约（委托 `draft_lease` 落地）——**等律师确认 LSA s.1(8)**。
- 第二档 API（OAuth）：护照结论、本人申请 / 租约 / 账期、针对某租约的草稿、消息只读、房源发布写——Supabase 作授权服务器，同意页自建（约 3 天）。
- 租客自发起核验（Veriff / Flinks）——等生产凭证；费用 Stayloop 担并限次。
- 房东侧「找经纪」入口 + 反向发起委托；拆开 `source` 与 MLS 信息块（现在一填 MLS 号就被判成导入房源、收不到申请）。
- 年度收支表（T776 行项）导出。
- Webhook（Standard Webhooks：签名 / 幂等 / 多日重试）。
- 经纪付费档 $29（上线条件：#13 #14 #15 完成）；团队档 $59 暂不开售（无组织成员模型）。

### 3.3 不做（并写进产品边界）
- **在线收租 / 代收**：FINTRAC MSB + RPAA + 持有资金三条合规线叠在新公司上；再评估需同时满足：消费者报告机构注册完成、律师书面意见、在管租约 ≥ 200 份且房东明确要自动扣款、能承受登记与 AML 成本。
- **LTB 代填 / 代送 / 代选表**、改写官方 PDF 分发。
- **OREA Form 400 本体**（`lib/lease/trreb.ts` 的「Form 400 structure」渲染器要改名或只留给房东）。
- **MLS / DDF / Realtor.ca** 任何数据路径；带看日历与找房（无数据）。
- 向租客收费的任何功能（产品决定；RTA s.134 本身禁的是与房源相关 / 替房东行事的收费）；按姓名查公开记录与评分对第三方开放（注册前）；「替租客查房东」的评价报告（对个人房东可能同样是消费者报告，需律师意见）。

## 6. 法规核查回执（`design/research/v1/legal-check-2026-10.md`）

七组法规全部对照官方原文核过（e-Laws 接口 RTA / LSA / TRESA / CRA / 567/05；laws-lois；FINTRAC；央行；OPC；ontario.ca 版权页；OREA 条款；LTB 手册与表格页）；读不到的只有 FINTRAC / 央行两个登记库与 O. Reg. 43/24。四稿引语基本准确，16 处措辞已按清单在各稿顶部标注修正。对本讨论稿有影响的结论：
- **平台做 N 表的边界是 LSA s.1(5)，不是 s.1(8)**：不选表、不建议送达方式、不判断该不该发，每个值来自房东输入或租约行（甲 #5 的门槛已改）。
- **「AI 不能代经纪谈条款」的依据是 LSA s.1(6) 4**；若 Stayloop 只涉 RTA 租约，TRESA s.5(1)(j) 反而让它整体免注册。商业房源检索这类隐藏技能要重新审视。
- **租客侧全免费是产品决定**，RTA s.134 本身禁的是与房源相关 / 替房东行事的收费；文案里不要写成「法律禁止」。
- **护照 API 的同意基础是 PIPEDA 4.3**，不是 CRA s.8(1)(b)（那是对报告机构的限制条款）；同意页要补用途、境外 / 留存风险句、拒绝不影响站内使用。
- **标准租约是 Crown copyright**：法定必用、免费下载，但不复制官方 PDF 加功能（经纪填表 = 我们自己的表单 + 官方 PDF 链接）。
- **LTB 手册明文：参与出租的经纪不得在 LTB 代理当事人**——经纪工具里不出现任何「替客户跟进 LTB」的说法。
- 同行是否已登记 MSB、Stripe Connect 是否在代理豁免之外，本轮未能复核；在线收租「不做」的结论不依赖这两点（FINTRAC 通知与 RPAA 定义原文已核实）。

## 7. 补充对标：liv.rent / RealMaster / HouseSigma（用户 2026-10-13 点名，原稿 `design/research/v1/benchmark-livrent-realmaster-housesigma-2026-10.md`）

**它们怎么处理 PropTx 的问题**：HouseSigma 与 RealMaster 都是**自己注册的经纪公司**（HouseSigma Inc. Brokerage，条款写明「Affiliated VOW Partner registered with TRREB」；RealMaster 挂靠 Avion Realty Inc., Brokerage，App 由另一法人发行），以会员身份拿 VOW 数据、只给注册登录用户看。liv.rent 不是经纪公司（条款「not a broker」），房源靠房东 / 物业公司自发与企业集成；页脚称 TRREB 数据经一家经纪公司协议展示——正是我们被拒的那种形态。
**对 Stayloop**：注册经纪公司的硬成本不高（RECO、保险、TRREB / OREA / CREA 会费合计约每年两三千加元），真正的门槛是一位合格的 Broker of Record 和整家公司进入 TRESA 监管；而且 **AI 禁令跟着会员身份走**——成为会员后约束对象只是从供应商变成会员本人，HouseSigma 2026-07 上线的 SigmaAI 聊天没有公开说明是怎么在规则内做的，不能据此推定对我们放行。所以这条路解决不了「开放 API 给其他 AI」，只能解决自家找房，且与「不做经纪业务」的定位相反。
**可以学的**：RealMaster 2026-10-09 新条款首次写明允许用户发起的「Personal Agent」实时访问（不得留存 / 建索引 / 训练）——可直接作我们 API / MCP 条款的范本；HouseSigma 的「登录后看历史」与中文界面证明 GTA 华人用户是真实细分市场（HouseSigma 英 / 简中，RealMaster 英 / 简 / 繁 / 韩）；三家都没有代办 + 审批、规则引擎、文件取证筛查、服务市场、只追加的消息证据链。
**可以合作的**：把 Stayloop 房东直租房源经 liv.rent 企业集成同步出去（等有 ≥30 套真实房源再谈）；向 HouseSigma 旗下租赁经纪推经纪筛查与委托工具（它们没有筛查，我们不收转介费）。RealMaster 没有公开合作入口。
**新增拍板项**：7. 是否给「自己注册经纪公司」这条路留口（建议不留，理由如上）；8. API / MCP 条款是否采用 RealMaster 的「Personal Agent」措辞（建议采用）。
