# 助手页快捷卡片：从「模板填空」到「分步引导」（2026-09-27）

用户截图（`/tenant/agent`，点「发起报修」）：输入框里出现
`我要报修：【哪里，如厨房 / 卫生间】【什么问题】，【从什么时候开始】，【是否紧急】。请整理成报修工单发给房东。`
要求：「重新制作这些卡片，不是简单复制这个标题内容到输入，要有一个一步步引导的过程给这个输入。」

## 1. 现状与它的问题

09-23 之前卡片直接**发送示例句**（「厨房水槽漏水…」），模型把示例当成事实。09-23 改成**模板 + 【占位符】进输入框**、
服务端 `hasUnfilledTemplate` 拒绝在未填模板上出卡片。它挡住了「把示例当事实」，但把负担全推给了用户：

- 一整行 `【…】【…】【…】` 要在文本框里逐个替换，手机上尤其难；
- 没有告诉用户**可以选什么**（哪些位置、什么算紧急、进门许可有哪三种）；
- 用户少填一项，模型再追问一轮——本来一步能出的工单变成三轮对话；
- 紧急件没有「现在先做什么」的提示（关总阀 / 拉闸 / 燃气离开）。

## 2. 别人怎么做（可借的只有方法）

| 模式 | 代表 | 做法 | 对我们的启示 |
|---|---|---|---|
| 一点即发的 prompt starter | Muse、ChatGPT 建议提示、Gemini chips | 卡片文字原样发出 | 演示很好，登录后会把示例当事实——已经吃过亏 |
| 先问清再执行 | Perplexity Pro Search（多选芯片 + 自由输入）、ChatGPT Deep Research | 模型先问 1–3 个澄清问题，用户点选后再跑 | **芯片 + 自由输入**这个交互是对的；但每一轮都要一次模型调用，慢、贵、匿名预览也要花钱 |
| 对话式表单 / 槽位填充 | Intercom Fin、Drift、Dialogflow slot filling、Rasa Forms、Typeform | 一次一个问题、快捷回复、进度、Enter 下一步、结束前确认 | **确定性、零成本、即时**；产物是一句完整的话 + 结构化槽位 |
| 分段式搜索 | Airbnb（Where → When → Who + 摘要条）、Uber「Where to?」 | 已答的项显示为摘要芯片，点回去改 | 摘要条解决「三步前选错了」 |
| 结构化表单 | Linear / Notion 模板、Slack Workflow 表单、iOS 快捷指令「每次询问」 | 字段 + 提交前预览 | 最后一步「确认并发送」 |

综合：**对话里的一张引导卡**（AI-native：对话就是页面，不跳表单页），一次一问、芯片优先、可自由输入、
已答项成摘要芯片可回改、紧急分支带「先做什么」、可选的附件步、最后一步预览整句再发送；全程不调模型。

## 3. 定稿设计

- **数据层 `lib/agent/intake.ts`（纯函数）**：每张卡一个 `IntakeSpec`——`steps[]`（`ask / hint / options / multi / input:
  text|textarea|money|date|number / optional / attach`）+ `compose(query, lang)`。`compose` 产出**没有任何占位符的完整一句**，
  并保证能被现有的确定性解析器读懂：找房句里的「预算 $2,500 以内」「1 房」「我有宠物」分别命中 `budgetFromText /
  bedsFromText / petsFromText`（硬约束层）；报修句里紧急类别写成 `没有暖气 / 漏水严重 / 停电 / 门锁失效 / 燃气味`，
  命中执行器的 `isEmergencyMaintenance`。
- **组件 `components/agent/IntakeCard.tsx`**：卡头（图标 · 标题 · 第 i 步 / 共 n 步 · ×）、细进度条、摘要芯片（已答项，点击回改）、
  问题 + 提示、芯片（单选无输入框的步骤点选即进下一步；多选 / 带输入框的要按「下一步」）、输入框（Enter = 下一步）、
  紧急选项红色 + 「先做这件事」提示、附件步（照片 / 租约 PDF，≤3 个 ≤4 MB，与输入条同一套读取器）、可选步可「跳过」、
  最后一步 = 预览整句（可改）+ 附件 → **发送** 或 **放进输入框自己改**。Esc / × 关闭回到卡片网格；手机 375px 下芯片换行、输入框 ≥16px。
- **接线 `AgentChat`**：工作台页（登录或匿名预览）与登录后的首页 hero 点卡片 = 打开引导卡（`guided = live || hero`）；
  匿名首页 hero 仍发示例句（那是演示）。卡片副标题从模板改成「N 步 · 问什么」。`template` 字段退役，深链的 `【…】` 预填与
  服务端闸门保留。
- **14 张卡全部有引导**（租客 4 / 房东 5 / 经纪 5）；知识类问题（租约与押金、合规边界、盖章）用 1–2 步选「关注点 + 场景」，
  产出一句更具体的问题；事务类（找房 / 报修 / 发房源 / 定价 / 带看）3–7 步。
- **不做**：模型驱动的逐轮追问（成本与延迟）；把引导卡做成独立表单页（离开对话）；在引导里问 OHRC 受保护特征
  （家庭状况、来源国等）——带看准备包只问「房东授权回答的范围」，筛查只问材料与同意状态，目标租金标明「只作参考不是门槛」。
